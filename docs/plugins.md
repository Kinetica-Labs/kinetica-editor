# Плагины на Python — за пять минут

**Плагин или скрипт?** Плагин остаётся в редакторе и даёт ему новое умение: действие над выделением, формат файла,
компонент с ручками, инструмент, панель, контроллер в такте. Построить сцену кодом — ряд кубиков, робота с датчиком —
это не плагин, а скрипт: файл Python, который отработал и ушёл ([scripts.md](scripts.md), `examples/scripts/`).

Плагин — один файл `plugin.py` в своей папке. Без сборки, без манифеста, только стандартная библиотека Python 3.
Плагины проекта живут в отдельном репозитории **kinetica-plugins**; в редакторе — только хост
(`editor/PluginHost.cpp`) и SDK (`clients/python/kinetica/plugin.py`).
Каждая функция с `@command` становится командой редактора:

- кнопкой в подменю **«Плагины → <имя плагина>»** (клавиша — если дадите свою и она свободна);
- строкой поиска команд (**Ctrl+K**);
- вызовом в консоли — `ed.my_tools_lift(height=0.2)`;
- операцией API для скрипта (`tools/ke_editor.py`);
- **инструментом MCP** для ИИ-агента, со строгой схемой полей: тип, единица, диапазон, значение по умолчанию.

## 1. Создать

**Плагины → Новый плагин…** и имя — например `my_tools` (русское имя запишется латиницей: «Мой плагин» → `moy_plagin`).
Редактор кладёт заготовку в папку плагинов пользователя, запускает её и открывает файл. Кнопка «Поднять выделенное» —
в «Плагины → my_tools».

То же из кода или агентом: `ed.plugin_new(name="my_plugin")` — в ответе путь к файлу.

## 2. Написать

```python
from kinetica.plugin import command, field


@command(label="Поднять выделенное")
def lift(scene, height: float = field(0.1, unit="м", range=(-1.0, 1.0), label="На сколько")):
    """Поднять выделенные объекты - одна правка, сколько бы их ни было."""
    chosen = scene.editor.selection
    if chosen:
        scene.move(*chosen, by=(0, height, 0))
    print("поднято", len(chosen))  # видно в консоли API
    return {"moved": len(chosen)}
```

Это и есть заготовка, которую кладёт «Новый плагин…»: новое действие редактора над тем, что выделено.

- **К сцене — два слоя, и только они.** `scene` — та же объектная модель, что в консоли редактора:
  `scene.objects["Куб 1"]`, `scene.add("box", role="rigid")`, `scene.move(...)`, `scene.editor.selection`. Для операции,
  которой в ней нет слова, — `scene.ed.<операция>(...)`, как `ed.<операция>(...)` в консоли: строку, опробованную в
  консоли, вставляйте в плагин как есть. Список операций — `ops_list`. Провод под ними (`client`) плагину не виден.
- Файл запускает сам редактор (`python -m kinetica.plugin plugin.py`): в конце файла ничего вызывать не нужно.
- `print(...)` и любая ошибка — сразу в **консоли API** под именем плагина.
- `key="Ctrl+Shift+R"` у `@command` — своя клавиша; занятую редактор не даёт и пишет в консоли, у кого она.
- `field(...)` — поле команды: значение по умолчанию, `unit`, `range`, `label`, `choices`, `help`. Из полей
  кнопка строит форму, MCP — схему инструмента. Простое значение по умолчанию (`solid: bool = True`) тоже поле.
- `joint=field(ref="joint", label="Сустав")` — **объект сцены**, а не id руками: форма предлагает суставы сцены по
  именам (выделенный — первым), агент передаёт id, а функция получает сам объект: `joint.drive(target=0.5)`. Слово —
  вид из `scene_list {kind}`: `joint`, `body` (тело с ролью «твёрдое»), `encoder` и другие виды датчиков, `sensor`,
  `camera`, `light`, `driver`… Объект другого вида отвергается с перечнем подходящих.
- Всё, что команда меняет в сцене, — **один шаг отмены** (Ctrl+Z), сколько бы правок она ни сделала.
- Каждый её вызов виден в консоли строкой Python с подписью `[плагин имя]`.

## 3. Сохранить — и сразу проверить

Сохраните файл: редактор перезапускает плагин примерно за 0,2 с, и кнопка обновляется. Ошибки указывают на ваш код:

- ошибка внутри команды — в ответе: `плагин «my_plugin»: plugin.py:14: ZeroDivisionError: division by zero`;
- ошибка при загрузке файла — в строке состояния: «⚠ Плагин «my_plugin» упал: plugin.py:3: …» и кнопка «Перезапустить».
  Редактор при этом работает дальше: плагин — отдельный процесс;
- ошибка в потоке, который плагин запустил сам, — «⚠ Плагин «my_plugin»: ошибка в фоне — plugin.py:13: …», плагин живёт;
- папку плагина удалили — редактор забывает его.

Аргументы проверяются по полям **до** вызова: `count: 0 вне 1…30`, `нет поля «colour»; поля: count, gap`.
Значение не подрезается молча — редактор говорит, что не так.

## Где живут плагины

| Папка | Что |
|---|---|
| репозиторий плагинов проекта — **kinetica-plugins** (Плагины → Добавить папку плагинов…, редактор запомнит) | плагины проекта (пример — `cubes`) |
| папка пользователя (**Плагины → Папка моих плагинов**) | ваши плагины; сюда кладёт «Новый плагин…» |
| `KE_PLUGINS=<папка>` | ещё одна папка |

Папка плагина, появившаяся при работающем редакторе, сама не подхватывается: **Плагины → Перезапустить плагины** или
операция `plugin_scan` просматривают папки заново. `plugin_scan {folder: "<папка>"}` — то же, что «Добавить папку
плагинов…»: папка запоминается. Где редактор ищет плагины — `plugin_list`, поле `folders`.

Автоматические прогоны — самотест, снимки — плагинов не запускают: их результат не зависит от того, что
у человека установлено. Самотест группы `plugins` запускает свой плагин сам.

`plugin_list` отвечает, какие плагины работают, какие упали и почему, и какие команды они дали.

## Как это устроено

Плагин-процесс по контракту [editor-plugin](contracts/editor-plugin.md). Редактор запускает
`python -m kinetica.plugin plugin.py` с портом API и токеном. Плагин регистрирует команды, ждёт вызовов и отвечает на
каждый — по одному соединению того же API, через который работают скрипты, консоль и агенты. Эта служебная проводка
(`plugin_register`, `plugin_wait`, `plugin_reply`, `plugin_panel_set`) не видна в `ops_list`, консоли, журнале и MCP:
это не действие человека. Хуки запуска (`@on_play`, `@on_tick`, `@on_stop`) отвечают по своему проводу и в своём потоке
(`editor/RunHooks.h`): такт идёт от симуляции к плагину и обратно, не дожидаясь окна. Код: `editor/PluginHost.cpp`
(окно), `clients/python/kinetica/plugin.py` (SDK).

## 4. Каждый кадр «Пуска»: контроллер или физика

«Плагины → Новый плагин…» предлагает три заготовки: **команда**, **контроллер робота**, **физика мира**. Две последние
живут в «Пуске»: функция с `@on_tick` вызывается каждый кадр **до** следующего шага — симуляция ждёт её ответа,
поэтому прогон повторим, а `dt` честный.

```python
from kinetica.plugin import on_play, on_tick, on_stop


@on_tick
def control(scene, dt, sensors):        # sensors: {id: {"kind": "encoder", "reading": 0.41, ...}} - как их видит робот
    return {7: {"target": 0.8}}         # сустав: target / velocity; драйвер: duty


@on_tick(world=True)
def wind(scene, dt, bodies):            # bodies: {id: {"position", "velocity", "angular_velocity", "mass"}} - истина движка
    return {i: {"force": [2.0, 0, 0]} for i in bodies}   # Н за кадр, в центре масс (ветер, магнит, тяга…)
```

- Контроллер видит **только датчики** — истины ему не дают (контракт наблюдаемости). Расширение физики
  (`world=True`) видит тела, как их знает движок, и толкает их силами.
- Команды — не правки сцены: ни шага отмены, ни строки журнала; «Стоп» возвращает сцену как была.
- `@on_play` и `@on_stop` — один раз на «Пуск» и «Стоп».
- Заготовка **«Контроллер робота»** замыкает контур: каждый сервопривод с энкодером идёт по медленной волне, а то, чего
  энкодер недосчитал (серво — пружина, вес звена её прогибает), копится в цель. В примере `robot-arm.kscene`
  энкодеры стоят на всех шарнирах; своему суставу — «Датчик ▾ → Энкодер» или `joint.add_encoder(reference=0)`:
  без известного нуля энкодер отдаёт только счёт, не угол. Сустав без энкодера заготовка не трогает.
- Такт не ждёт перерисовки окна: пустой `on_tick` стоит около 0,3 мс на кадр (UR5e). Хук и команда одного плагина не
  выполняются одновременно: долгая команда задерживает такт.
- Те же два пути есть и в API: `sensor_read` (показания без истины) и `robot_command` (команды и силы).
- **Свои числа на графике.** Элемент панели `ui.chart` — линии во времени запуска; линия — значение панели, и каждый
  `show(...)` из `on_tick` ставит на ней точку во времени своего кадра. Историю (последнюю минуту) хранит и рисует
  редактор; значения уходят вместе с ответом такта, без лишних запросов:

  ```python
  from kinetica.plugin import on_tick, show, ui

  ui.panel("Привод", ui.chart("Ошибка привода", {"error": "ошибка", "trim": "поправка"}, unit="рад"),
           ui.value("error", "Сейчас"), place="bottom")


  @on_tick
  def control(scene, dt, sensors):
      ...
      show(error=wanted - measured, trim=trim)     # точка на каждой линии и слово «Сейчас»
  ```

## 5. Компонент на объекте и оранжевые ручки

```python
from kinetica.plugin import component, field, on_tick


@component(label="Ветряк")
class Turbine:
    radius = field(1.0, unit="м", range=(0.1, 5.0), label="Радиус", handle="radius")   # точка вдоль x объекта
    hub = field((0.0, 0.5, 0.0), label="Ступица", handle="point")                    # точка в системе объекта
    power = field(100.0, unit="Вт", range=(0, 1000), label="Мощность")


@on_tick(world=True)
def blow(scene, dt, bodies):
    for shape, values in Turbine.instances(scene):   # [(id, {"radius": 1.0, ...}), ...]
        ...
```

- «Ветряк» появляется в **«+ Добавить компонент»** любой фигуры; карточка в инспекторе рисуется из полей; правка —
  один шаг отмены и строка `ed.component_set(...)` в журнале. Строка в файле сцены:
  `component turbines.turbine power 100 radius 1 hub 0,0.5,0`.
- Поля с `handle=` — **оранжевые точки** на выбранной фигуре: `"radius"` (вдоль x), `"length"` (вдоль `axis`, по
  умолчанию y), `"point"` (тащится в плоскости экрана), `"dial"` — **угол** вокруг `axis`: точка на круге вокруг
  фигуры (`field(30.0, unit="°", handle="dial")` — в градусах, без «°» — в радианах), `"box"` — **размер** из трёх
  чисел: по точке на гранях +x, +y, +z. Подсветка до щелчка, значение у курсора, Esc — отмена; щелчок по точке
  никогда не меняет выделение.
- Поле со строкой по умолчанию (`word = field("текст", label="Слово")`) — строка ввода в карточке: правка по Enter
  или при уходе из поля.
- `@on_change` над функцией `f(scene)` — «мои компоненты в сцене изменились»: компонент повесили, поправили в карточке,
  сняли, отменили правку, открыли сцену; и один раз при старте плагина. Здесь плагин перерисовывает то, что рисует
  для своих компонентов (пример — плагин `formula` в репозитории kinetica-plugins). В «Пуске» не зовётся.
- Плагин не запущен — карточка говорит «не запущен», значения хранятся как есть.
- В API: `component_set {id, type, values}`, `component_remove`, `component_list {type?}`.

## 6. Рисование поверх вида

```python
from kinetica.plugin import draw, on_tick


@on_tick(world=True)
def forces(scene, dt, bodies):
    draw.segments("силы", arrows)                  # пары точек: стрелки сил на телах
    draw.points("метки", points, color="#33ccff", size=4)
    draw.label("v", (0, 1.2, 0), "3.2 м/с")
```

- Кольцо и габарит своего гизмо — `draw.circle(key, центр, радиус, axis="y")` и `draw.box(key, центр, размер)`.
- Линия через точки — `draw.line`, пары — `draw.segments`, точки — `draw.points`, надпись — `draw.label`,
  `draw.clear(key)` / `draw.clear()` — убрать своё. Координаты — метры мира, цвет `"#rrggbb"` или `(r, g, b)`,
  по умолчанию оранжевый.
- Залитая картинка — `draw.fill(key, контуры, object=..., at=(0, 0.4, 0), space="label", scale=0.05)`: контуры — строки
  `"M x y L x y C x1 y1 x2 y2 x y Z"` в своих единицах, x вправо, y вверх. `space="world"` — на своей плоскости в мире
  (единица — `scale` метров, поворот `turn`), `"label"` — на экране в точке мира, лицом к зрителю, `"screen"` — в кадре
  на месте `place=(x, y)` (доли вида); в двух последних единица — `scale` высоты вида. С `object` картинка принадлежит
  объекту: едет с ним в правке и в «Пуске», щелчок по ней выделяет объект. Она рисуется поверх сцены: тело впереди
  её не закрывает.
- Тот же ключ заменяет рисунок. Нарисованное во время «Пуска» исчезает на «Стопе», из команды — остаётся,
  пока его не уберут или пока плагин не остановится.
- Из `on_tick` рисунки уходят вместе с ответом такта — без лишних запросов. Не правка сцены: ни шага отмены,
  ни строки журнала.
- Любой клиент API рисует операцией `view_draw {key, line?, segments?, points?, circle?, box?, text?, fill?, at?, color?, clear?}` —
  так агент показывает план пути.

## 7. Инструмент в виде

```python
from kinetica.plugin import command, field


@command(label="Дерево", tool=True)
def plant(scene, point, normal, object, height=field(2.0, unit="м")):
    scene.add("cylinder", position=point, size=(0.2, height, 0.2))
```

- Оранжевая кнопка с первой буквой встаёт на полку слева от вида, под инструментами гизмо.
- Нажата — щелчок в виде вызывает команду: `point` — где щёлкнули, `normal` — нормаль поверхности,
  `object` — id объекта под мышью (0 — пол). Остальные аргументы берутся из панели плагина, иначе по умолчанию.
- **Инструмент с перетаскиванием** — команда, у которой есть ещё и `to`: нажали в `point`, протянули, отпустили в
  `to` (`to_object` — объект под ней); пока тянете, вид рисует линию и её длину. Щелчок — перетаскивание нулевой
  длины. Так делаются «стена от точки до точки», «связать два объекта».
- Esc, другой инструмент полки или повторное нажатие — выход; вид вращают правая и средняя кнопки, как всегда.
- Всё, что команда сделала за один щелчок, — один шаг отмены. Агент вызывает ту же команду с `point` сам.

## 8. Импорт файлов

```python
from kinetica.plugin import command


@command(label="URDF — робот", opens=".urdf")
def load(scene, path):
    ...                                  # строит сцену теми же операциями, что и всё остальное
    return {"note": "6 звеньев, 5 суставов"}
```

- Формат появляется в **«Файл → Импорт…»** (Ctrl+I) рядом с OBJ и STL. Файл можно и **перетащить в вид**.
- Команда получает `path`; всё, что она построила, — один шаг отмены. `note` из ответа видна в строке состояния.
- Агент вызывает ту же команду: `ed.urdf_load(path=...)`.

**URDF приходит с редактором** — плагин `plugins/urdf/plugin.py`:
- звенья становятся фигурами в группе с именем робота: коробка, цилиндр, шар, меш STL или OBJ;
- вместо визуального DAE берётся форма столкновений, пути `package://` ищутся в папках над файлом;
- суставы `revolute`, `continuous` и `prismatic` становятся приводами, которые держат позу, с пределами из URDF;
  `fixed` становится сваркой, корень закреплён;
- URDF стоит осью z вверх, редактор — осью y: робот поворачивается целиком;
- масса — масса звена из `inertial`, делённая на объём его формы.

Пример: `examples/robot-arm.urdf`.

## Чего пока нет

Компонента со своим тактом (`tick(self, dt)` у класса, датчик и привод — его поля), событий о выделении и о правках
сцены помимо своих компонентов (`@on_change`) и состояния плагина, переживающего его перезапуск, —
[editor-plugin](contracts/editor-plugin.md), «Дальше».

## Плагин руками ИИ-агента

Агент через MCP (`tools/ke_editor_mcp.py`) делает то же, что человек. Каждая операция редактора — инструмент с пометкой:
запрос — «только чтение», правка сцены и состояние окна — «не разрушает» (правка — один шаг отмены). Сотня инструментов —
около 50 КБ в контексте агента при каждом старте; профиль `KE_MCP_FAMILIES=scene,assembly,sim,plugin` (в `env` сервера
в `.mcp.json`) оставляет инструментами только эти семейства, остальное доступно через `editor_call`.

Плагин агент пишет так:

1. `plugin_new {name}` → путь к файлу (или своя папка с `plugin.py` в одной из папок плагинов и `plugin_scan`);
2. пишет файл своими инструментами;
3. `plugin_list` → `работает` или ошибку с файлом и строкой;
4. вызывает новую команду как инструмент MCP.

Навык для Claude Code — `.claude/skills/kinetica-plugin/SKILL.md`.
