# Контракт editor-plugin — схема, команда, плагин

**Редактор — кисть, плагины — картины.** Кисть — удобный мир и механизмы управления им: гизмо, камера,
выбор, инспектор, отмена, консоль, журнал; она должна быть безупречной и стабильной. Всё, что
расширяет мир, — новые роботы, датчики, задачи, импорт, контроллеры — пишется плагинами поверх кисти.

Редактор — клиент. Всё, что в нём есть, вплоть до последней кнопки, — команда, которую можно написать
строкой Python. Любой код редактора и любой плагин, встроенный или сторонний, на C++ или Python,
выражается тремя понятиями: **схема**, **команда**, **плагин**.

## Три правила

1. **Кнопки без команды не бывает.** Кнопка, пункт меню, клавиша, жест мышью (гизмо, магнит сборки)
   вызывают команду по имени и ничего больше. Кнопку плагин не создаёт: он её описывает, окно рисует.
2. **Каждое действие видно как код.** Консоль внизу окна печатает строку Python для каждого вызова,
   кто бы его ни сделал — рука, скрипт, агент. Строку можно скопировать и выполнить снова; она пишется
   в журнал (JSON lines, только дописывается) и отменяется как одна правка.
3. **Встроенное и стороннее устроены одинаково** — цель, к которой идём точками расширения ниже: выделение,
   гизмо, отмена, инспектор и журнал одни и те же для встроенного и плагинного. Сегодня плагин даёт команды и
   панель; карточки, ручки, инструменты встроенных частей пока написаны на C++.

## Три понятия

**Схема — описание данных.** Поле: имя (в файле, API и Python одно), тип, единица, диапазон, шаг,
подпись, справка. Схема — набор полей объекта, компонента, настройки или аргументов команды. Из одной
схемы получаются: строка файла сцены и её проверка, проверка аргументов API, поле в инспекторе,
атрибут в Python, справка для человека и агента.

**Команда — действие.** Имя `область_действие`, схема аргументов и ответа, справка, выполнение;
вопрос только читает, правка — один шаг отмены с обратной правкой ([operations](operations.md)).
Из реестра команд получаются: кнопки, меню, поиск команд, строки консоли, обёртки Python, инструменты
MCP для агентов.

**Плагин — пакет схем и команд**, один файл `plugin.py` без манифеста. Он добавляет команды, свою панель,
компоненты, ручки, инструменты, рисование и импорт — всё из раздела «Что есть сейчас».

| График | `ui.chart(заголовок, линии, unit, x)` — линии; линия — значение панели. С `x` (имя значения панели или `{имя: слова}`) ось — шаг, а не время: точку на линии ставит любой `show()` / `plugin_panel_set`, где есть и `x`, и значение линии, из любого потока, не только из такта; видны все точки от первой до последней, `x` не больше последнего (назад или тот же: новое обучение с поколения 1) — новая история; подсказка называет шаг ближайшей точки; ось подписана словами `x`, подсказка говорит «поколение 12», а не «в 2,4 с». Рисует график только вкладка «Графики» — в разделе с заголовком панели после графиков сцены (в любой раскладке, и в «Нормировать»); «Что показывать» слева выбирает, какие его графики видны; в самой панели на месте графиков — кнопка «Графики ▸» с их заголовками, она открывает вкладку ([ui](ui.md)); панель ушла (плагин остановлен, перезапущен, удалён) — раздел уходит с ней (ряды разделяются через `shared_ptr`). Плагин только называет линии и отдаёт числа; в описании панели это ключи `x` и `x_label` | `PluginPanel.cpp`, `PlotPanel.cpp`, `TrackChart.h` |
| Картинка | `ui.svg(имя, height)` — картинка в панели: плагин присылает SVG значением панели `имя` (`show(имя='<svg …>')`, из такта или любого потока), редактор рисует его по ширине панели с сохранением пропорций, не выше `height` пикселей. Пустой или неверный SVG — тихая заглушка «нет картинки»; перерисовка идёт по тому же 25-герцовому такту панели, что и остальное. Плагин даёт данные, не виджеты; в описании панели это `{"kind": "svg", "name", "height"?}` | `PluginPanel.cpp` |
| Сцена | два слоя и только они: `scene` — объектная модель консоли (`scene.objects`, `scene.add(..., role=...)`, `scene.editor.selection`); операция, которой в ней нет слова, — `scene.ed.<операция>(...)`, как `ed.<операция>(...)` в консоли. Провод под ними плагину не виден | `clients/python/kinetica/scene.py` |
| Жизнь | редактор запускает `python -m kinetica.plugin plugin.py` с портом и токеном; команды — одно соединение API на плагин, хуки запуска — свой провод (см. «Такт»); сохранили файл — перезапуск за ~0,2 с; `print` и ошибки — в консоли API; падение — в строке состояния с файлом и строкой; папку удалили — плагин забыт; новую папку плагина при работающем редакторе подхватывает `plugin_scan` (с `folder` — добавляет и запоминает папку плагинов, как «Добавить папку плагинов…»); `plugin_list` называет папки, где плагины ищутся | `PluginHost.cpp` |
| Конец | `@on_quit`: один раз, когда плагин кончается - редактор закрывается или перезапускает его (SIGTERM, потом через 0,7 с kill), связь с редактором оборвалась; остановить поток прибора, закрыть порт - чтобы плата не слала в порт, который никто не читает | `PluginHost::stop`, `~PluginHost`, `clients/python/kinetica/plugin.py` |
| Такт | `@on_play`, `@on_tick`, `@on_stop`: каждый кадр «Пуска» до следующего шага (лок-шаг, ждёт ≤ 0,5 с); контроллер получает датчики как их видит робот (и пульты сцены - `kind: controller`, `values`: каждое действие, как его держат), отвечает командами (`target`, `velocity`, `duty`); `@on_tick(world=True)` — расширение физики: тела (истина движка) → силы за кадр; команды вне отмены и журнала, «Стоп» их забывает. Хуки идут по своему проводу и потоку, мимо потока окна: кадр уходит из потока симуляции и ответ возвращается в него же, окно получает рисунки и ошибки хука уже после; события одного плагина приходят по порядку — play, каждый tick, stop; код автора выполняется по одному куску — команда или хук. Замер (UR5e, пустой `on_tick`): 0,3 мс сверх шага; через поток окна было 33–61 мс | `RunHooks.h`, `SimController.cpp`, `MainWindowPlugins.cpp`, `RobotWorld::command/push` |
| Компонент | `@component` класса с `field`: «+ Добавить компонент», карточка из полей (поле-строка `field("текст")` — строка ввода: правка по Enter или при уходе из поля), строка `component <плагин>.<имя> ключ значение…` в блоке объекта; без плагина — карточка «не запущен», слова хранятся; `Тип.instances(scene)`; API `component_set` / `component_remove` / `component_list`. Компонент ложится на объект любого вида — фигуру, группу, свет, камеру, сустав, датчик, батарею, секвенцию: через API и в файле сцены одинаково. У копии-экземпляра компоненты — её мастера, как и роли: `component_set` пишет в мастер, `component_list` называет экземпляр со значениями мастера, самостоятельная копия экземпляра уносит их с собой. Карточку и «+ Добавить компонент» окно пока рисует только у фигуры | `SceneBuilderComponents.cpp`, `SceneOpsActions.cpp` |
| Инструмент | `@command(tool=True)`: оранжевая кнопка на полке инструментов; щелчок в виде вызывает команду с `point`, `normal`, `object` и значениями панели плагина; один щелчок — один шаг отмены; Esc — выход. Команда с `to` — инструмент с перетаскиванием: нажали в `point`, отпустили в `to` (`to_object` — что под ней), между ними линия с длиной; щелчок — перетаскивание нулевой длины. Вид отдаёт команде только те из этих аргументов, что она объявила | `Viewport::setPluginTool`, `Viewport::dragTool`, `PluginHost::useTool` |
| Рисование | `draw.line / segments / points / label / circle / box / clear` и операция `view_draw`: по ключу, метры мира; `circle` (кольцо вокруг оси или направления) и `box` (двенадцать рёбер) — кольца и габариты своего гизмо; их считает сама операция (`view_draw {circle: {centre, radius, axis?}, box: {centre, size}}`), Python только передаёт слова, так что они есть у любого клиента; из `on_tick` — вместе с ответом такта, исчезает на «Стопе»; не правка: без отмены и журнала. `draw.fill(key, контуры, object, at, space, scale, turn, place)` — залитая плоская картинка поверх сцены: контуры — строки `M x y L x y C x1 y1 x2 y2 x y Z` в своих единицах (x вправо, y вверх); `space="world"` — на своей плоскости в мире, единица `scale` метров; `"label"` — на экране в точке мира `at`, лицом к зрителю; `"screen"` — в кадре на месте `place` (доли вида от левого верхнего угла); в двух последних единица — `scale` высоты вида. `object` — картинка принадлежит объекту и едет с ним в правке и в «Пуске»: в мире лежит на нём (`at`, `turn` в его осях), метка висит на `at` от него по осям мира; щелчок по картинке выделяет объект. Глубины у неё нет: тело впереди её не закрывает. `draw.label(..., space="screen", place, background, glow)` — слова в кадре, строки вверх от `place`, на подложке `(r, g, b, a)`, как у субтитров; `glow` (0..1) — ореол цвета рисунка вокруг слов, выноски и картинки; `draw.glow(key, object, strength, colour)` — светится сама деталь (её силуэт в виде): та, что агент ставит сейчас | `Viewport::setDrawing`, `ViewportFills.cpp`, `EditorOpsInput.cpp`, `clients/python/kinetica/plugin.py` |
| Изменение | `@on_change` над функцией `f(scene)`: зовётся, когда компонент этого плагина повесили на объект, изменили или сняли — рукой в карточке, скриптом, отменой, открытием сцены — и один раз при старте плагина; здесь плагин держит свои рисунки в согласии со своими компонентами. Не правка: шага отмены не делает; в «Пуске» не зовётся — изменённое за запуск придёт после «Стопа», если осталось | `PluginHost::componentsChanged`, `clients/python/kinetica/plugin.py` |
| Импорт | `@command(opens=".urdf")`: формат в «Файл → Импорт…» и перетаскивание файла в вид; команда получает `path`, всё построенное — один шаг отмены; URDF — плагин, который поставляется с редактором | `PluginHost::openFile`, `MainWindow::importFile`, `plugins/urdf/plugin.py` |
| Вывоз | `@command(saves=".urdf")`: формат в «Файл → Экспорт…»; команда получает `path` и сцену не меняет | `PluginHost.cpp` (`formats(true)`, `openerFor(…, true)`), `MainWindow::exportScene` |
| Устаревшее имя | `@command(obsolete="io_formats_urdf_load")`: команда переехала, старое имя живёт (имена только растут) — операция отвечает, функция пересылает к новой; кнопки, пункта меню и формата «Импорт…» у неё нет, справка называет новое имя | `PluginHost.cpp` (`Command::obsolete`), `clients/python/kinetica/plugin.py` |
| Ручки | `field(..., handle="radius" \| "length" \| "point" \| "dial" \| "box")` — оранжевые точки на выбранной фигуре: `dial` — угол вокруг `axis`, точка на круге вокруг фигуры (градусы, если единица поля «°», иначе радианы; круг нарисован); `box` — размер из трёх чисел, по точке на гранях +x, +y, +z. Тащит общая механика ручек ядра (подсветка, значение у курсора, Esc), отпустили — одна `component_set` | `ColliderGuides.h ShapeHandle`, `ViewportTools.cpp`, `SceneBuilderComponents.cpp` |
| Заготовки | `plugin_new {name, kind: command \| controller \| world}` — каждая сразу делает что-то в сцене; контроллер замыкает контур: сервоприводы с энкодером идут по волне, поправка — по показанию энкодера | `clients/python/kinetica/plugin_template*.py` |

Служебная проводка (`plugin_register`, `plugin_wait`, `plugin_reply`, `plugin_panel_set`, с токеном плагина) —
транспорт, не действие человека: её нет в `ops_list`, консоли, журнале и MCP.

**Граница обещания.** Автору плагина обещаны слова SDK из этой таблицы (`@command`, `field`, `@component`, `ui.*`,
`@on_play` / `@on_tick` / `@on_stop`, `@on_change`, `@on_quit`, `draw.*`) и операции редактора, которые плагин зовёт. Проводка не обещана и
меняется вместе с SDK: плагин запускает сам редактор и кладёт свой пакет `kinetica` первым в `PYTHONPATH`
(`editor/PythonRuntime.h`), так что SDK и редактор всегда одной версии. Плагин, который говорит с редактором мимо
SDK, этой проводкой пользоваться не должен.

**Словарь элементов панели** — единственная прослойка между плагином и виджетами:

| Элемент | Что рисует окно |
|---|---|
| `button(команда)` | кнопка; щелчок вызывает команду с полями панели, которые у команды есть |
| `slider(поле)`, `number(поле)` | слайдер или поле числа с единицей и диапазоном |
| `toggle(поле)`, `choice(поле)`, `vector(поле)`, `text(поле)` | флажок, список, x / y / z, строка |
| `value(имя)` | значение, которое плагин показывает через `show()` |
| `chart(заголовок, линии)` | график во вкладке «Графики» (в панели — кнопка к ним): по линии на значение панели, точка на каждый `show()` из такта; единица — в заголовке, имена линий — в легенде и подсказке под мышью |
| `svg(имя, height)` | картинка: SVG, присланный `show(имя=...)`, по ширине панели |
| `section(заголовок, ...)`, `row(...)`, `label(текст)` | складной раздел, ряд, подпись |

Описание приходит в окно как данные (JSON по API). Рендерер на Qt живёт только в окне (`editor/`): замена Qt не
затронет ни один плагин. Панель — вкладка инспектора; `place="bottom"` принимается и значит то же: первый уровень окна
не плагина ([ui](ui.md)).

### Перевод

Имя плагина (его папка) и имена команд — английские и навсегда: на них держатся операции, MCP, скрипты. Надписи для
человека плагин пишет на одном языке (у плагинов проекта — русском, как окно) и кладёт переводы каталогом рядом:
`i18n/<язык>.json` — `{"Мозг": "Brain", "Обучить": "Train"}`, язык — код окна (`en`, `ru`). Окно, запуская плагин,
само переводит по каталогу всё, что плагин описал: `label`, `title`, `text`, `help`, `unit`, `x_label` команд, полей,
панели, графиков и компонентов и первые слова значения панели (`ui.value(..., default=)`; у полей `default` — данные); варианты выбора (`enum`) показывает словами каталога, а команде отдаёт значение плагина.
Слова, которые плагин составляет на ходу, — через `tr("…")` из `kinetica.plugin`: шаблон — ключ каталога,
`tr("поколение {g}").format(g=4)`. Нет каталога или слова в нём — исходное слово. Каталог сохранили — плагин
перезапустился, как от правки `plugin.py`; каталог, которого при запуске не было, окно увидит со следующего запуска
(сохраните `plugin.py`). Проверка: самотест `KE_EDITOR_TEST=plugin`, `testWords`.

## Пример (работает сегодня)

Команда — заготовка «Нового плагина…» (`clients/python/kinetica/plugin_template.py`, урок — [docs/plugins.md](../plugins.md)).
Панель к ней: поле, кнопка и значение, которое команда кладёт через `show`:

```python
from kinetica.plugin import show, ui

# в lift заготовки, перед return:  show(moved=len(chosen))
ui.panel("Подъём", ui.section("Выделенное", ui.number("height", 0.3, unit="м", label="На сколько"),
                              ui.button(lift, "Поднять")), ui.value("moved", "Поднято", 0))
```

## Чего пока нет

Компонента с тактом: `tick(self, dt)` у класса компонента, его датчик и привод как поля.

## Граница

Собственное сложное рисование (3D-вид, графики, Лаборатория) остаётся встроенным частям: интерфейс из схем хорош для
полей и кнопок и неудобен для сложных видов. Плагину — рисование поверх вида и
элемент `chart`: рисует редактор, плагин даёт числа.

Встраиваемых плагинов (`.so`/`.dll` с интерфейсом на C) нет: один вид — плагин-процесс, его падение не роняет редактор.

## Как проверяется

- Самотест, группа `plugins`: плагин из папки `KE_PLUGINS` приходит кнопкой; команда — один шаг отмены; такты отвечены,
  пока поток окна спит (лок-шаг не идёт через окно); форма и
  панель вызывают её с полями; ошибка — с файлом и строкой и откатом; сохранение перезапускает; падение при загрузке
  и в потоке — в строке состояния; русское имя папки — латиницей; удалённая папка — плагин забыт.
