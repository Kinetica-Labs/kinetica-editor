# Контракт editor-plugin — схема, команда, плагин

**Редактор — кисть, плагины — картины.** Кисть — удобный мир и механизмы управления им: гизмо, камера,
выбор, инспектор, отмена, консоль, журнал; она должна быть безупречной и стабильной. Всё, что
расширяет мир, — новые роботы, датчики, задачи, импорт, контроллеры — пишется плагинами поверх кисти.

Редактор — клиент. Всё, что в нём есть, вплоть до последней кнопки, — команда, которую можно написать
строкой Python. Любой код редактора и любой плагин, встроенный или сторонний, на C++ или Python,
выражается тремя понятиями: **схема**, **команда**, **плагин**. Почему именно так и на какие работы
это опирается — `docs/design/foundations.md`.

## Три правила

1. **Кнопки без команды не бывает.** Кнопка, пункт меню, клавиша, жест мышью (гизмо, магнит сборки)
   вызывают команду по имени и ничего больше. Кнопку плагин не создаёт: он её описывает, окно рисует.
2. **Каждое действие видно как код.** Консоль внизу окна печатает строку Python для каждого вызова,
   кто бы его ни сделал — рука, скрипт, агент. Строку можно скопировать и выполнить снова; она пишется
   в журнал (JSON lines, только дописывается) и отменяется как одна правка.
3. **Встроенное и стороннее устроены одинаково** — цель, к которой идём точками расширения ниже: выделение,
   гизмо, отмена, инспектор и журнал одни и те же для встроенного и плагинного. Сегодня плагин даёт команды и
   панель; карточки, ручки, инструменты встроенных частей пока написаны на C++.

## Три понятия

**Схема — описание данных.** Поле: имя (в файле, API и Python одно), тип, единица, диапазон, шаг,
подпись, справка. Схема — набор полей объекта, компонента, настройки или аргументов команды. Из одной
схемы получаются: строка файла сцены и её проверка, проверка аргументов API, поле в инспекторе,
атрибут в Python, справка для человека и агента.

**Команда — действие.** Имя `область_действие`, схема аргументов и ответа, справка, выполнение;
вопрос только читает, правка — один шаг отмены с обратной правкой ([operations](operations.md)).
Из реестра команд получаются: кнопки, меню, поиск команд, строки консоли, обёртки Python, инструменты
MCP для агентов.

**Плагин — пакет схем и команд**, один файл `plugin.py` без манифеста. Сегодня он добавляет команды и свою панель;
компоненты, ручки, инструменты, рисование и импорт — точки расширения из раздела «Дальше».

## Что есть сейчас (Python, плагин-процесс)

| Что | Как | Где |
|---|---|---|
| Поле | `field(default, unit, range, label, choices, help)`; простое значение по умолчанию — тоже поле. `field(ref="joint")` — объект сцены вместо числа руками: слово — вид из `scene_list {kind}` (`joint`, `body`, `encoder` и другие виды датчиков, `sensor`, `camera`, `light`, `driver`…); форма предлагает объекты этого вида по именам, выделенный — первым; вызов даёт id, без него или с объектом другого вида — отказ с перечнем имеющихся; команда получает сам объект (`scene.objects[id]`); в компоненте хранится id, на карточке — список | `python/kinetica/plugin.py`, `PluginHost.cpp`, `SceneBuilderComponents.cpp` |

| Сцена | два слоя и только они: `scene` — объектная модель консоли (`scene.objects`, `scene.add(..., role=...)`, `scene.editor.selection`); операция, которой в ней нет слова, — `scene.ed.<операция>(...)`, как `ed.<операция>(...)` в консоли. Провод под ними плагину не виден | `python/kinetica/scene.py` |
| Жизнь | редактор запускает `python -m kinetica.plugin plugin.py` с портом и токеном; команды — одно соединение API на плагин, хуки запуска — свой провод (см. «Такт»); сохранили файл — перезапуск за ~0,2 с; `print` и ошибки — в консоли API; падение — в строке состояния с файлом и строкой; папку удалили — плагин забыт; новую папку плагина при работающем редакторе подхватывает `plugin_scan` (с `folder` — добавляет и запоминает папку плагинов, как «Добавить папку плагинов…»); `plugin_list` называет папки, где плагины ищутся | `PluginHost.cpp` |
| Такт | `@on_play`, `@on_tick`, `@on_stop`: каждый кадр «Пуска» до следующего шага (лок-шаг, ждёт ≤ 0,5 с); контроллер получает датчики как их видит робот, отвечает командами (`target`, `velocity`, `duty`); `@on_tick(world=True)` — расширение физики: тела (истина движка) → силы за кадр; команды вне отмены и журнала, «Стоп» их забывает. Хуки идут по своему проводу и потоку, мимо потока окна: кадр уходит из потока симуляции и ответ возвращается в него же, окно получает рисунки и ошибки хука уже после; события одного плагина приходят по порядку — play, каждый tick, stop; код автора выполняется по одному куску — команда или хук. Замер (UR5e, пустой `on_tick`): 0,3 мс сверх шага; через поток окна было 33–61 мс | `RunHooks.h`, `SimController.cpp`, `MainWindowPlugins.cpp`, `RobotWorld::command/push` |
| Компонент | `@component` класса с `field`: «+ Добавить компонент», карточка из полей (поле-строка `field("текст")` — строка ввода: правка по Enter или при уходе из поля), строка `component <плагин>.<имя> ключ значение…` в блоке объекта; без плагина — карточка «не запущен», слова хранятся; `Тип.instances(scene)`; API `component_set` / `component_remove` / `component_list`. Компонент ложится на объект любого вида — фигуру, группу, свет, камеру, сустав, датчик, батарею, секвенцию: через API и в файле сцены одинаково. У копии-экземпляра компоненты — её мастера, как и роли: `component_set` пишет в мастер, `component_list` называет экземпляр со значениями мастера, самостоятельная копия экземпляра уносит их с собой. Карточку и «+ Добавить компонент» окно пока рисует только у фигуры | `SceneBuilderComponents.cpp`, `SceneOpsActions.cpp` |
| Инструмент | `@command(tool=True)`: оранжевая кнопка на полке инструментов; щелчок в виде вызывает команду с `point`, `normal`, `object` и значениями панели плагина; один щелчок — один шаг отмены; Esc — выход. Команда с `to` — инструмент с перетаскиванием: нажали в `point`, отпустили в `to` (`to_object` — что под ней), между ними линия с длиной; щелчок — перетаскивание нулевой длины. Вид отдаёт команде только те из этих аргументов, что она объявила | `Viewport::setPluginTool`, `Viewport::dragTool`, `PluginHost::useTool` |
| Рисование | `draw.line / segments / points / label / circle / box / clear` и операция `view_draw`: по ключу, метры мира; `circle` (кольцо вокруг оси или направления) и `box` (двенадцать рёбер) — кольца и габариты своего гизмо; их считает сама операция (`view_draw {circle: {centre, radius, axis?}, box: {centre, size}}`), Python только передаёт слова, так что они есть у любого клиента; из `on_tick` — вместе с ответом такта, исчезает на «Стопе»; не правка: без отмены и журнала. `draw.fill(key, контуры, object, at, space, scale, turn, place)` — залитая плоская картинка поверх сцены: контуры — строки `M x y L x y C x1 y1 x2 y2 x y Z` в своих единицах (x вправо, y вверх); `space="world"` — на своей плоскости в мире, единица `scale` метров; `"label"` — на экране в точке мира `at`, лицом к зрителю; `"screen"` — в кадре на месте `place` (доли вида от левого верхнего угла); в двух последних единица — `scale` высоты вида. `object` — картинка принадлежит объекту и едет с ним в правке и в «Пуске»: в мире лежит на нём (`at`, `turn` в его осях), метка висит на `at` от него по осям мира; щелчок по картинке выделяет объект. Глубины у неё нет: тело впереди её не закрывает | `Viewport::setDrawing`, `ViewportFills.cpp`, `EditorOpsInput.cpp`, `python/kinetica/plugin.py` |
| Изменение | `@on_change` над функцией `f(scene)`: зовётся, когда компонент этого плагина повесили на объект, изменили или сняли — рукой в карточке, скриптом, отменой, открытием сцены — и один раз при старте плагина; здесь плагин держит свои рисунки в согласии со своими компонентами. Не правка: шага отмены не делает; в «Пуске» не зовётся — изменённое за запуск придёт после «Стопа», если осталось | `PluginHost::componentsChanged`, `python/kinetica/plugin.py` |
| Импорт | `@command(opens=".urdf")`: формат в «Файл → Импорт…» и перетаскивание файла в вид; команда получает `path`, всё построенное — один шаг отмены; URDF — плагин, который поставляется с редактором | `PluginHost::openFile`, `MainWindow::importFile`, `plugins/urdf/plugin.py` |
| Ручки | `field(..., handle="radius" \| "length" \| "point" \| "dial" \| "box")` — оранжевые точки на выбранной фигуре: `dial` — угол вокруг `axis`, точка на круге вокруг фигуры (градусы, если единица поля «°», иначе радианы; круг нарисован); `box` — размер из трёх чисел, по точке на гранях +x, +y, +z. Тащит общая механика ручек ядра (подсветка, значение у курсора, Esc), отпустили — одна `component_set` | `ColliderGuides.h ShapeHandle`, `ViewportTools.cpp`, `SceneBuilderComponents.cpp` |
| Заготовки | `plugin_new {name, kind: command \| controller \| world}` — каждая сразу делает что-то в сцене; контроллер замыкает контур: сервоприводы с энкодером идут по волне, поправка — по показанию энкодера | `python/kinetica/plugin_template*.py` |

Служебная проводка (`plugin_register`, `plugin_wait`, `plugin_reply`, `plugin_panel_set`, с токеном плагина) —
транспорт, не действие человека: её нет в `ops_list`, консоли, журнале и MCP.

**Граница обещания.** Автору плагина обещаны слова SDK из этой таблицы (`@command`, `field`, `@component`, `ui.*`,
`@on_play` / `@on_tick` / `@on_stop`, `@on_change`, `draw.*`) и операции редактора, которые плагин зовёт. Проводка не обещана и
меняется вместе с SDK: плагин запускает сам редактор и кладёт свой пакет `kinetica` первым в `PYTHONPATH`
(`editor/PythonRuntime.h`), так что SDK и редактор всегда одной версии. Плагин, который говорит с редактором мимо
SDK, этой проводкой пользоваться не должен.

**Словарь элементов панели** — единственная прослойка между плагином и виджетами:

| Элемент | Что рисует окно |
|---|---|
| `button(команда)` | кнопка; щелчок вызывает команду с полями панели, которые у команды есть |
| `slider(поле)`, `number(поле)` | слайдер или поле числа с единицей и диапазоном |
| `toggle(поле)`, `choice(поле)`, `vector(поле)`, `text(поле)` | флажок, список, x / y / z, строка |
| `value(имя)` | значение, которое плагин показывает через `show()` |
| `chart(заголовок, линии)` | график: по линии на значение панели, точка на каждый `show()` из такта; единица — в заголовке, имена линий — в легенде и подсказке под мышью |
| `section(заголовок, ...)`, `row(...)`, `label(текст)` | складной раздел, ряд, подпись |

Описание приходит в окно как данные (JSON по API). Рендерер на Qt живёт только в окне (`editor/`): замена Qt не
затронет ни один плагин. Панель — вкладка инспектора (`place="right"`) или нижней панели (`place="bottom"`).

## Пример (работает сегодня)

```python
from kinetica.plugin import command, field, show, ui


@command(label="Поднять выделенное")
def lift(scene, height: float = field(0.1, unit="м", range=(-1.0, 1.0), label="На сколько")):
    """Поднять выделенные объекты - одна правка, сколько бы их ни было."""
    chosen = scene.editor.selection
    if chosen:
        scene.move(*chosen, by=(0, height, 0))
    show(moved=len(chosen))
    return {"moved": len(chosen)}


ui.panel("Подъём", ui.section("Выделенное", ui.number("height", 0.3, unit="м", label="На сколько"),
                              ui.button(lift, "Поднять")), ui.value("moved", "Поднято", 0))
```

## Дальше: точки расширения

Чтобы на плагинах строилось что угодно — робот, игра, 3D-редактор — и всё работало одинаково, начиная с гизмо,
у плагина будут те же механизмы, что у встроенного. Каждая точка
сводится к уже существующим полю, операции, отмене и журналу — новых путей для отмены и инспектора не появляется.

1. ~~Такт контроллера~~ — **сделан** (см. «Что есть сейчас»).
2. ~~Компонент~~ — **сделан**. 3. ~~Ручки = поля~~ — **сделаны** («radius», «length», «point», «dial», «box»).
4. ~~Инструмент = команда~~ — **сделан**. 5. ~~Рисование поверх вида~~ — **сделано** (см. «Что есть сейчас»).
6. ~~Импорт~~ — **сделан**; первый формат — URDF, плагин, который поставляется с редактором (`plugins/urdf`).
7. ~~Поле-ссылка на объект сцены~~ — **сделано**: `field(ref="joint")` (см. «Что есть сейчас»).
8. **Компонент с тактом** — `tick(self, dt)` у класса компонента, его датчик и привод как поля (пример ниже).

Так будет выглядеть первый робототехнический плагин:

```python
from kinetica import component, field, sensor, actuator


@component(label="ПИД сустава")
class JointPid:
    encoder = sensor("encoder")     # показание без истины
    motor = actuator("driver")      # команда мимо журнала, сброс на «Стопе»
    target = field(0.5, unit="рад", range=(-3.14, 3.14), label="Цель")
    kp = field(2.0, range=(0, 50))

    def tick(self, dt):
        self.motor.duty = self.kp * (self.target - self.encoder.angle)
```

## Граница

Собственное сложное рисование (3D-вид, графики, Лаборатория) остаётся встроенным частям: интерфейс из схем хорош для
полей и кнопок и неудобен для сложных видов. Плагину — рисование по точке расширения 5 и
элемент `chart`: рисует редактор, плагин даёт числа.

Встраиваемые плагины (`.so`/`.dll` с интерфейсом на C) — не раньше, чем понадобится второй движок физики или горячий
цикл 1 кГц; до тех пор один вид — плагин-процесс: его падение не роняет редактор.

## Как проверяется

- Самотест, группа `plugins`: плагин из папки `KE_PLUGINS` приходит кнопкой; команда — один шаг отмены; такты отвечены,
  пока поток окна спит (лок-шаг не идёт через окно); форма и
  панель вызывают её с полями; ошибка — с файлом и строкой и откатом; сохранение перезапускает; падение при загрузке
  и в потоке — в строке состояния; русское имя папки — латиницей; удалённая папка — плагин забыт.
- Самотест, группа `plugins`, гизмо плагина: точка угла, перетащенная на четверть круга, даёт 90° в поле; точка на грани
  меняет один размер из трёх; инструмент с `to` получает обе точки перетаскивания; у каждого — один шаг отмены.
- Самотест, группа `plugins`, поле-ссылка: вид и обязательность в схеме инструмента; отказ без поля и с объектом другого
  вида; команда получает объект; форма и карточка компонента предлагают объекты сцены по именам. Заготовка контроллера:
  сервопривод с энкодером идёт по своей волне.
- `tools/test_plugin_sdk.py` — Python-сторона без окна: схема полей, строка ошибки, провод хуков запуска (порядок событий,
  слияние команд, истина тел только хуку физики).
