# Контракт editor-plugin — схема, команда, плагин

**Редактор — кисть, плагины — картины.** Кисть — удобный мир и механизмы управления им: гизмо, камера,
выбор, инспектор, отмена, консоль, журнал; она должна быть безупречной и стабильной. Всё, что
расширяет мир, — новые роботы, датчики, задачи, импорт, контроллеры — пишется плагинами поверх кисти.

Редактор — клиент. Всё, что в нём есть, вплоть до последней кнопки, — команда, которую можно написать
строкой Python. Любой код редактора и любой плагин, встроенный или сторонний, на C++ или Python,
выражается тремя понятиями: **схема**, **команда**, **плагин**. Почему именно так и на какие работы
это опирается — `docs/design/foundations.md`.

## Три правила

1. **Кнопки без команды не бывает.** Кнопка, пункт меню, клавиша, жест мышью (гизмо, магнит сборки)
   вызывают команду по имени и ничего больше. Кнопку плагин не создаёт: он её описывает, окно рисует.
2. **Каждое действие видно как код.** Консоль внизу окна печатает строку Python для каждого вызова,
   кто бы его ни сделал — рука, скрипт, агент. Строку можно скопировать и выполнить снова; она пишется
   в журнал (JSON lines, только дописывается) и отменяется как одна правка.
3. **Встроенное и стороннее устроены одинаково.** Конструктор, инспектор, графики, Лаборатория,
   консоль, физика — плагины по тому же контракту. Нет возможностей, которых сторонний плагин не может
   повторить (кроме собственного рисования — см. «Граница»).

## Три понятия

**Схема — описание данных.** Поле: имя (в файле, API и Python одно), тип, единица, диапазон, шаг,
подпись, справка. Схема — набор полей объекта, компонента, настройки или аргументов команды. Из одной
схемы получаются: строка файла сцены и её проверка, проверка аргументов API, поле в инспекторе,
атрибут в Python, справка для человека и агента.

**Команда — действие.** Имя `область_действие`, схема аргументов и ответа, справка, выполнение;
вопрос только читает, правка — один шаг отмены с обратной правкой ([operations](operations.md)).
Из реестра команд получаются: кнопки, меню, поиск команд, строки консоли, обёртки Python, инструменты
MCP для агентов.

**Плагин — пакет схем и команд.** Манифест плюс код. Плагин добавляет:
- компоненты — схема плюс поведение на кадре; компонент вешается на любой объект сцены (объект — это
  id и набор компонентов; «Твёрдое» и «Коллайдер» — такие же компоненты);
- команды;
- описание своих панелей и места своих кнопок;
- виды дорожек Sequencer — схема значения ключа плюс правило между ключами. Секвенция
  (`SequenceObject`, упрощённая Level Sequence из Unreal) хранит анимацию отдельно от объектов: привязка
  по id → дорожка ключей. Сейчас есть один встроенный вид — «преобразование»: позиция по прямой, поворот
  по кратчайшей дуге. Плагин добавит, например, «угол сустава» или «событие», не трогая ядро:
  редактор рисует ключи и бегунок, плагин задаёт значение в момент времени.

## SDK плагина — без Qt, без движка, без ядра

Плагин зависит только от SDK: заголовки C++ без Qt и без сторонних библиотек и пакет Python
`kinetica` с тем же смыслом. В SDK четыре вещи:

| Что | C++ | Python |
|---|---|---|
| Поле и схема | `Field`, `Schema` | `field(...)` |
| Команда | `Command` (имя, схема, выполнение, отмена) | `@command(...)` |
| Описание панели | дерево `UiNode` из словаря ниже | `ui.section(...)`, `ui.slider(...)` |
| Хуки кадра компонента | `play`, `frame`, `stop` | методы класса компонента |

Сцену плагин читает и меняет только командами ядра, а не прямым доступом к классам.

**Словарь элементов панели** — единственная прослойка между плагином и виджетами:

| Элемент | Что рисует окно |
|---|---|
| `button(команда)` | кнопка; щелчок вызывает команду |
| `slider(поле)`, `number(поле)` | слайдер или поле числа с единицей и диапазоном из схемы |
| `toggle(поле)` | флажок |
| `choice(поле)` | выпадающий список |
| `vector(поле)` | x / y / z |
| `color(поле)`, `file(поле)`, `text(поле)` | цвет, путь, строка |
| `section(заголовок, ...)`, `row(...)` | складной раздел, ряд |
| `label(текст)` | подпись |

Описание приходит в окно как данные: от C++-плагина — структурой, от Python-плагина — тем же JSON по
API. Рендерер на Qt живёт только в окне (`editor/`). Замена Qt не затронет ни один плагин.

Места для кнопок и панелей: верхняя панель «Создать», вкладки боковой панели («Сцена», «Объект»,
«Мир»), нижние вкладки (консоль, графики), меню, контекстное меню вида, поиск команд.

## Пример

```python
from kinetica import plugin, component, field, command, ui

@plugin("suction-cup", version="1.0")
class SuctionCup(component):
    radius = field(0.02, unit="м", range=(0.005, 0.1), label="Радиус")
    vacuum = field(60.0, unit="кПа", range=(0, 90), label="Разрежение")

    @command(label="Захват", key="G")
    def grip(self, on: bool = True):
        """Включить или выключить присоску."""
        ...

    def frame(self, world):
        ...

    def panel(self):
        return ui.section("Присоска", ui.slider("radius"), ui.slider("vacuum"), ui.button("grip"))
```

Из этого редактор сам получает: поля в инспекторе, строку компонента в файле сцены, кнопку «Захват»
и клавишу G, команду `suction_cup_grip` в консоли, журнале, отмене и у агента в MCP. Ни строки Qt.

## Два вида плагинов

| | Плагин-процесс | Встраиваемый плагин |
|---|---|---|
| Язык | любой (Python, Rust, C++) | C++ с интерфейсом на C |
| Связь с окном | API по сети (`--api`, JSON lines) | `.so` / `.dll` в папке `plugins/` |
| Падение плагина | редактор работает дальше | роняет редактор |
| Для чего | команды, импорт и экспорт, генераторы, анализ, контроллеры раз в кадр, ROS и железо | горячие циклы: движок физики, сопоставление стерео, контроллер 1 кГц |

Встроенные части окна — C++-классы, собранные вместе с редактором, — пользуются тем же SDK: те же
схемы, команды и описания панелей.

## Манифест и версии

`plugin.json`: имя, версия, какие контракты и каких версий нужны (`editor-plugin@1`, `operations@1`),
вид (процесс или встраиваемый), команда запуска. Несовместимый плагин редактор не загружает и говорит
почему. Несовместимое изменение контракта — только с новой версией.

## Граница

Собственное рисование (3D-вид, графики, Лаборатория) остаётся встроенным частям: сгенерированный из
схем интерфейс хорош для полей и кнопок и неудобен для сложных видов (Pawson, Naked Objects).
Сторонний плагин получает для этого рисование отладочных линий, точек и подписей в 3D-виде через
Probe и каналы графиков.

## Меньше кода за счёт структуры

- Кнопки, меню и поиск команд строятся из реестра команд — рукописного кода «кнопка → вызов» нет.
- Инспектор, чтение и запись файла сцены, проверка аргументов и справка строятся из схем.
- Обёртки Python и инструменты MCP генерируются из `ops_list`.
- Число строк окна до и после шага пишется в его коммит: улучшение структуры видно как минус строки
  при тех же зелёных тестах.

## Цикл улучшения и плагины руками ИИ-агентов

1. Человек или агент работает в редакторе; каждое действие — строка кода в журнале.
2. По журналу видны повторяющиеся цепочки команд; из цепочки пишется плагин — новая команда с кнопкой.
3. Тесты соответствия проверяют, что плагин выполняет контракт и ничего не ломает.
4. Плагин сразу доступен всем: кнопкой человеку, строкой Python скрипту, инструментом MCP агенту.

Агенту для этого нужны контракты (`docs/contracts/*.md`), список команд (`ops_list`), журнал и тесты
соответствия. Добавляются заготовка (команда создаёт папку плагина с манифестом, классом и тестом) и
навык Claude Code «как написать плагин» в `.claude/skills/`.

## Как проверяется

- Самотест обходит каждую кнопку, пункт меню и клавишу окна: щелчок дал ровно одну команду из
  реестра и её строку Python в консоли.
- Тесты соответствия плагина (`ke_conformance`): его команды есть в `ops_list`, каждая отвечает
  `{"ok": ...}`, правка отменяется, панель описана словарём SDK, манифест совместим.

## Порядок внедрения

1. Окно старого редактора возвращается целиком (идёт).
2. SDK: `Field`/`Schema`, `Command`, `UiNode`, рендерер описаний панелей в окне.
3. Кнопки и меню — из реестра команд; инспектор — из схем; роли — компоненты.
4. Плагин-процесс: регистрация чужих команд и панелей по API; пакет `kinetica` для плагинов на Python.
5. Тесты соответствия, заготовка плагина, навык для агента.
6. Встраиваемые плагины с интерфейсом на C — с появлением второго движка физики.
