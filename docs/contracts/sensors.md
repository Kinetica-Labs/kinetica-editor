# Контракт sensors — датчики робота

Заголовки:
- сигнальная цепочка `src/devices/Signal.h`;
- устройства `Imu`, `Sonar`, `ForceTorque`, `Encoder`, `EncoderMeasurement` в `src/devices/`;
- паспорт и таблицы моделей `src/scene/SensorSpec.h`;
- датчик в сцене `SensorObject` в `src/scene/SceneGraph.h`; его виды: Encoder, Imu, Sonar, Touch, Wrench, Effort, Stereo.

Опрос датчиков в работающем мире (`src/sim`) ещё не сделан.

## Главное правило — наблюдаемость

Управление и восприятие робота получают только то, что выдал бы настоящий датчик: с дискретностью,
шумом, смещением, частотой, задержкой, диапазоном и отказами. Истинные позы, углы и скорости из
physics, пиксельные id и истинная глубина OpenGL входами робота не бывают: они есть только у
привилегированного контура проверки. Обратная связь по суставам идёт через модель энкодера и
декодирование импульсов. IK/FK по командам — прогноз, не доказательство исполнения. Идеальный датчик —
только явно помеченный режим reference (`noise 0`).

## Устройство: композиция, а не иерархия

Датчик собирается из четырёх независимых частей. Наследования «датчик → IMU → MPU-6050» нет.

| Часть | Что делает | Чего не знает |
|---|---|---|
| Крепление | тело и поза на нём (`SceneObject`: parent, position, rotation) | вида и модели |
| Зонд физики (`src/sim`) | истинная величина из мира, только через контракт `PhysicsWorld`: удельная сила и угловая скорость в точке, эхо лучей, координата, реакция и усилие сустава, сила контактов через грань | паспорта |
| Сигнальная цепочка (`Signal.h`) | ступени паспорта: такт, чувствительность и смещение (вытягиваются раз по зерну), белый шум, фильтр первого порядка, насыщение, отсчёты слова. Каждую ступень включает её число | физики |
| Выход | как читает контроллер: число, отсчёты, импульсы TRIG/ECHO (`Sonar`), фронты A/B/Z (`Encoder`) | физики |

Вид датчика — это рецепт: какой зонд, какие цепочки и какой выход.
- **IMU** = инерциальный зонд + две цепочки на одном такте: гироскоп и акселерометр.
- **Сила-момент** = зонд сустава + две цепочки: сила и момент.
- **Сонар** = лучи + дрожь дальности + импульсы.

Модель — это данные, а не код.

## Паспорт и таблицы моделей

**Поля паспорта.** У вида с паспортом (imu, sonar, wrench) есть список полей `specFields(kind)`. У каждого поля:
- ключ — столбец таблицы и слово файла сцены, единица записана в самом ключе;
- подпись и единица для человека;
- допустимый диапазон;
- значение для датчика без модели.

Числа берутся в тех единицах, в каких их пишет техописание:
- шум — плотность на √Гц;
- допуски смещения и чувствительности — ± (их устройство читает как 3σ);
- точность и шум датчика силы — 3σ.

**Таблицы** — `data/sensors/<вид>.csv`, по строке на модель:
- столбцы `model`, поля вида и `source` — техописание, его ревизия и выбранная конфигурация;
- пустая ячейка — «не указано», поле берёт своё значение;
- строки `#` — комментарии.

Таблиц две: программы (рядом с ней, в сборке из исходников — `data/sensors` дерева) и человека (`<данные программы>/sensors`). Строка человека заменяет строку программы с тем же именем модели. Окно читает обе при запуске и перечитывает, когда файл меняется. Новая модель — новая строка таблицы, без кода.

**Датчик хранит свой паспорт.** `SensorObject::model` — откуда взяты числа, `spec` — сами числа. В файле сцены это строки `model "…"` и `spec ключ число …`, поэтому сцена читается одинаково и без таблиц. Число, введённое поверх модели, принадлежит датчику; карточка тогда пишет «(числа изменены)». Новый датчик получает первую модель своей таблицы, а если таблицы нет — значения полей. Старый файл без `spec` читается со значениями полей.

**API:**
- `sensor_models {kind?}` — поля видов и модели таблиц;
- `sensor_spec {sensor, model?, spec?}` — модель, затем числа поверх неё. Ответ — паспорт с `as_model`;
- `assembly_sensor {…, model?, spec?}`.

В Python: `body.add_imu(model="…")`, `sensor.set_spec("…", rate_hz=400)`, `sensor.spec`, `sensor.model`.

## Модели устройств (что воспроизводят)

| Устройство | Выход | Что воспроизводит |
|---|---|---|
| Энкодер | фронты A/B/Z с временем в целых наносекундах, счёт ×4 | `floor(θ 4N / 2π)` при любой скорости; направление по порядку A/B; индекс раз в оборот |
| IMU | ускорение и угловая скорость в отсчётах слова | частота выдачи, фильтр полосы, диапазон и разрядность, шум по плотности, смещения и ошибка чувствительности по зерну |
| Сонар | импульсы TRIG / ECHO | расстояние до ближайшего зеркального эха в конусе луча, дрожь по точности, цикл, спад ECHO без эха |
| Сила-момент | сила и момент с частотой паспорта | шум, смещения, диапазон |

Число зерна (`seed`) делает шум повторяемым: одно зерно — те же биты, то же устройство.

Не моделируются:
- перекрёстная чувствительность осей, нелинейность, дрейф от температуры;
- FIFO и шина у IMU;
- диффузное отражение и многократное эхо у сонара.

## Что проверяют тесты (`devices:`)

- **Энкодер:** счёт и времена фронтов.
- **IMU:**
  - частота, отсчёты полной шкалы, насыщение и шаг фильтра — против точных ответов;
  - шум и смещения — против распределения, из которого они берутся.
- **Сонар:** дрожь.
- **Паспорт:**
  - разбор таблицы и её ошибки;
  - модель в датчик и число поверх неё;
  - паспорт через файл сцены до бита;
  - таблицы программы читаются чисто, каждое число в диапазоне своего поля;
  - `sensor_spec` и `assembly_sensor` по имени модели.
