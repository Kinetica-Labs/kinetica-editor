# Контракт sensors — датчики робота

Заголовки: модели устройств `src/devices/` (`Encoder`, `EncoderMeasurement`, `Mpu6050`, `Hcsr04`,
`ForceTorque`); датчик в сцене — `SensorObject` в `src/scene/SceneGraph.h` (виды: Encoder, Imu, Sonar,
Touch, Wrench, Effort, Stereo). Опрос датчиков в работающем мире — этап переноса 4 (`src/sim`).

## Главное правило — наблюдаемость

Управление и восприятие робота получают только то, что выдал бы настоящий датчик: с дискретностью,
шумом, смещением, частотой, задержкой, диапазоном и отказами. Истинные позы, углы и скорости из
physics, пиксельные id и истинная глубина OpenGL входами робота не бывают: они есть только у
привилегированного контура проверки. Обратная связь по суставам идёт через модель энкодера и
декодирование импульсов. IK/FK по командам — прогноз, не доказательство исполнения. Идеальный датчик —
только явно помеченный режим reference.

## Модели (как в техописаниях)

| Устройство | Выход | Что воспроизводит |
|---|---|---|
| Энкодер | фронты A/B/Z с временем в целых наносекундах, счёт ×4 | `floor(θ 4N / 2π)` при любой скорости; направление по порядку A/B; индекс раз в оборот |
| MPU-6050 | регистры как в техописании (I²C) | диапазоны ±2..16 g, ±250..2000 °/с, частота 8 кГц / (1 + SMPLRT_DIV), фильтр DLPF, шум и смещения по зерну |
| HC-SR04 | импульсы TRIG / ECHO | расстояние до ближайшего эха, дрожь 1 мм (3σ = 3 мм), цикл 60 мс |
| Датчик силы | сила и момент 500 Гц | шум, смещения, диапазон |

Число зерна (`seed`) делает шум повторяемым: одно зерно — те же биты.

## Что проверяют тесты (`devices:`)

Счёт и времена фронтов энкодера; регистры MPU-6050 по техописанию; статистика его шума против
распределения, из которого он берётся; дрожь сонара.
