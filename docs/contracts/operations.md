# Контракт operations — API редактора

Заголовок: `src/scene/SceneOps.h` (реестр `sceneOps()`, `findSceneOp(name)`); правки с обратными —
`src/scene/SceneEdits.h`; формат сцены — `SceneGraph::save/load` (`src/scene/SceneGraph.cpp`).

Любое действие в редакторе — операция этого реестра: кнопка, магнит, консоль, скрипт и агент по
сети вызывают одни и те же операции. Новая возможность сначала становится операцией, потом кнопкой.

## Операция

| Поле | Значение |
|---|---|
| `name` | одно слово `область_действие`: `scene_put`, `assembly_attach`, `world_set` |
| `help` | строка справки для человека и агента |
| `args` | аргументы строкой справки: `{target: int, face?: '+x'..'-z'}` (`?` — необязательный) |
| `query` | вопрос: только читает граф |
| `edit` | правка: один шаг отмены у клиента; ошибка оставляет откат клиенту |
| `takesIds` | действует на `ids`; клиент подставляет выделение, если их нет |

`ops_list` называет род каждой операции (`kind`) — по нему клиент агента размечает свои инструменты (MCP: «только
чтение», «не разрушает»): `query` — читает; `edit` — правит сцену, один шаг отмены; `window` — состояние и время окна
(выделение, гизмо, вид, пуск, пауза, шаг), сцена как она написана не меняется; `action` — остальное: запись файла,
возврат по журналу, остановка программы, команда плагина. `ops_list {families: ["scene", "sim"]}` отдаёт операции
только этих семейств.

Ответ — JSON (`core/Value.h`): `{"ok": true, ...}` или ошибка строкой с причиной. Действие отвечает
`{"id", "ids"}` — что окну выделить после него, и `{"note"}` — что включено попутно, словами.

## Гарантии

- Имя значит одно и то же везде: в окне, в консоли, у агента. Имена не переименовываются — это
  контракт с агентами и MCP.
- Строка аргументов операции — её схема (`editor/ArgsSchema.h`): из неё `ops_list` и MCP строят JSON Schema
  (тип, список слов, единица и значение по умолчанию в описании поля). Вызов с полем, которого в строке нет,
  с не тем типом или словом не из списка отвергается с перечнем полей — опечатка не теряется молча. Поля на `_`
  (`_py`) — транспорта, их не проверяют. Поле, которое код читает, обязано быть в строке: иначе вызов окна
  упадёт в самотесте.
- Неудачная команда плагина ничего не меняет: всё, что она успела сделать, откатывается одним шагом.
- `edit_undo` / `edit_redo` отвечают, что изменили: id объектов и мир.
- Каждая правка обратима через ядро правок (`getObject`/`putObject`/`setField`/`removeObject`,
  `getWorld`/`putWorld`) и становится строкой журнала JSON lines, который только дописывается.
- Формат сцены: строка на факт; `save → load → save` даёт тот же текст на любой локали; незнакомая
  строка или роль другой физики отвергается с номером строки и словом.
- Формат сцены — часть API: его строки принимают и отдают `scene_put`, `scene_set`, `scene_get`, `world_set`,
  `world_get`. Он только растёт:
  - ключ назван словом, порядок ключей в строке не важен, пропущенный ключ получает значение по умолчанию —
    файл и скрипт, написанные раньше, читаются всегда;
  - строка и ключ не переименовываются и не меняют смысл и единицу; слова в имени соединяет `_`
    (`contact_hertz`, `anchor_a`), как в аргументах операций;
  - незнакомое слово отвергается, а не теряется молча.

  Имя, которое ключ носил до этого правила (`contactHertz`, `anchorA`…), читается и сохраняется под новым —
  таблица `renamed` в `src/scene/SceneGraph.cpp`. Замок обещания — `tests/data/scene-format-1.kscene`: в нём
  каждая строка и каждый ключ формата на день обещания, файл не правится никогда. Новая строка или ключ —
  в новый файл-образец рядом, не в этот: `scene-format-2.kscene` — слово `kinematic` у роли `rigid` и строка
  `tags` у объекта любого вида; `scene-format-3.kscene` — строка `component` плагина у того, что не фигура;
  `scene-format-4.kscene` — `mass`, `center_of_mass` и `inertia` у роли `rigid`. Новое слово пишется в файл, только когда оно задано: сцену без него читает и
  редактор, который этого слова ещё не знает.
- Текст сцены разбирает только ядро. `scene_get {id}` отдаёт рядом с текстом блока его вид, имя и строки
  словами (число — числом); `scene_get {id, line, key, count}` и `world_get {line, key, count}` — значения после
  ключа, те самые, что пишут `scene_set` и `world_set {line, key, values}`; чего нет — `null`. Клиент — Python,
  плагин, агент — слова в тексте не ищет.

## Семейства

`scene_*` — список (весь или по виду: `scene_list {kind: "joint" | "body" | "encoder"…}` — из него выбирает поле-ссылка
плагина), блоки файла, добавить, удалить, группы, роли, перемещение; метки: `scene_tag {ids, tag, on?}` ставит слово
на объект любого вида — фигуру, сустав, датчик, батарею, секвенцию, — `scene_list {tag}` находит по нему,
`scene_get {id}` называет метки объекта; `world_*` — мир и строка
`physics`; `assembly_*` — магнит сборки, звенья, пресеты, суставы, приводы, датчики, питание, цели IK;
`controller_*` — пульты; `sequence_*` — секвенции (ключи, дорожки, проигрывание). Окно добавляет свои:
`sim_*` (пуск, стоп, шаг, запись дубля), `view_*`, файлы, `plugin_*` (плагины-процессы), `script_run`. Полный список с
аргументами — `ops_list`.

**Скрипт и плагин.** `script_run {file}` запускает файл Python, который строит или меняет сцену и заканчивается —
пример кодом, как скрипт в Blender. Скрипт — такой же клиент API, как консоль: `import kinetica as ke`,
`scene = ke.connect()`. Всё, что он сделал, — один шаг отмены; его `print()` приходит в консоль API и в ответ
операции (`output`); упавший скрипт ничего не меняет и называет свой файл и строку; одновременно идёт один скрипт.
`script_stop {}` прерывает идущий: это тот же исход, что падение, — сделанное отменяется, а сцена, оставленная в игре,
возвращается в правку.
Запуск: «Файл → Выполнить скрипт…», ключ `--script файл.py`, любая строка API. Примеры — `examples/scripts/`.
Плагин — другое: он остаётся и даёт редактору новое умение (формат файла, компонент, инструмент, панель, такт) —
[editor-plugin](editor-plugin.md).

## Что проверяют тесты

Реестр по именам: вопросы, правки, ответы, пакет; поле блока и мира читается и пишется в ядре по
строке и ключу (`actions:`); правки ядра и их обратные, позирование
сустава, сборка, IK, пути целей (`assembly:`); формат сцены (`scene graph:`); образец формата читается и
ни одно его слово не теряется, прежние имена ключей читаются (`scene format:`).
