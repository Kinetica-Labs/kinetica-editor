# Контракт operations — API редактора

Заголовок: `src/scene/SceneOps.h` (реестр `sceneOps()`, `findSceneOp(name)`); правки с обратными —
`src/scene/SceneEdits.h`; формат сцены — `SceneGraph::save/load` (`src/scene/SceneGraph.cpp`).

Любое действие в редакторе — операция этого реестра: кнопка, магнит, консоль, скрипт и агент по
сети вызывают одни и те же операции. Новая возможность сначала становится операцией, потом кнопкой.

## Операция

| Поле | Значение |
|---|---|
| `name` | одно слово `область_действие`: `scene_put`, `assembly_attach`, `world_set` |
| `help` | строка справки для человека и агента |
| `args` | аргументы строкой справки: `{target: int, face?: '+x'..'-z'}` (`?` — необязательный) |
| `query` | вопрос: только читает граф |
| `edit` | правка: один шаг отмены у клиента; ошибка оставляет откат клиенту |
| `takesIds` | действует на `ids`; клиент подставляет выделение, если их нет |

`ops_list` называет род каждой операции (`kind`) — по нему клиент агента размечает свои инструменты (MCP: «только
чтение», «не разрушает»): `query` — читает; `edit` — правит сцену, один шаг отмены; `window` — состояние и время окна
(выделение, гизмо, вид, пуск, пауза, шаг), сцена как она написана не меняется; `action` — остальное: запись файла,
возврат по журналу, остановка программы, команда плагина. `ops_list {families: ["scene", "sim"]}` отдаёт операции
только этих семейств.

Ответ — JSON (`core/Value.h`): `{"ok": true, ...}` или ошибка строкой с причиной. Действие отвечает
`{"id", "ids"}` — что окну выделить после него, и `{"note"}` — что включено попутно, словами.

## Хозяева операций

Операции исполняет хозяин: окно (`build/kinetica`, TCP, `--api`) или сцена без окна (`ke::Scene` в `src/api/Scene.h`;
следом ей служат `kinetica-core` — JSON-строки на stdin/stdout, ключи `--data-dir DIR`, `--version`, `--help` — и
`ke.Scene()` в Python с ключом `executable=`, переменной `KE_CORE`). Имена, поля, ответы и тексты ошибок общих операций
одни; логика одна, в ядре (`src/scene`, `src/sim`, `src/api`). Хозяин вправе иметь меньше операций (`ops_list` называет
все его операции; записи общих имён у обоих равны) и отвечает по-своему только там, где ему нужно то, чего нет у
другого: часы и поток, выделение, вид, экран, плагины, журнал сессий — у окна. Отличия, каждое с причиной:

- в сцене без окна нет `sim_play` и `sim_pause` (нет часов, время идёт по `sim_step`): имя называет `sim_step` и
  говорит, что часов нет;
- в её `sim_state` нет `frame_timing` (бухгалтерия окна и настенных часов); `step_ms` остался у обоих и есть часы
  машины, а не результат — любое сравнение его маскирует;
- операции с `ids` берут то, что им дали, а без `ids` отвечают собственными словами (`no objects to act on: pass ids`):
  выделения нет; окно подставляет выделенное. `scene_add_light` без `at` и `scene_add_camera` без `eye` берут центр
  сцены, окно — выделенное и точку взгляда; так же `scene_add_force` без `at`;
- относительный путь файла считается от каталога, где запущен хозяин;
- ошибки файлов сцена без окна говорит своими русскими словами (`не назван файл`, `нет файла «p»` и для относительного
  имени `(искали: /абсолютный/путь)`, `«p» - каталог, а не файл`, `файл «p» не читается`, `нет каталога «d» для файла
  «p»`, `файл «p» не записывается`), текст сцены, которая не разбирается, — тот же, что у окна; окно говорит словами Qt
  на языке системы;
- изменение формы сустава при построенном мире окно замечает кадром позже и пока отвечает `until_stop`, сцена без окна
  вызывает `RobotWorld::setJoints` на месте и отвечает `play_stopped` с `reload: "joints"`;
- неизвестную операцию сцена без окна называет по-своему: `нет операции «X» в kinetica-core (ops_list называет все её
  операции; выбор, вид, консоль, плагины и журнал есть только у окна)`;
- исключение внутри операции — ответ `{"ok": false, "error": "внутренняя ошибка: <что>"}`, граф такой, каким был;
- журнала нет: сценарий сам себе запись (`docs/constitution.md`, ст. II.6).

Тексты самой программы `kinetica-core` (stderr, каждая строка начинается с `kinetica-core: `; код выхода 0 — конец
ввода, `--version`, `--help`; 1 — исключение, ушедшее наверх; 2 — ключи или данные): `неизвестный ключ X`,
`--data-dir без значения`, `нет каталога sensors в «D» (--data-dir)` — ключ указал каталог без `sensors/`, и это
ошибка, а не повод искать дальше; без ключа ищут рядом с настоящим файлом программы (`data/`, `../data/`), затем в
дереве исходников: `нет каталога data/sensors (искали: ...); укажите --data-dir`; `таблицы датчиков: <строка>` — строка
таблицы не прочиталась, программа стартует. `sim_play` в ней отвечает `нет операции «sim_play» в kinetica-core: часов
нет, время идёт по sim_step (scene.run, scene.step)`. Пути файлов таблиц в `sensor_models` у хоста и окна пишутся
одинаково, без `..`. `id` запроса возвращается как число двойной точности: целое больше 2^53 теряет младшие цифры.

Замок — `tests/SceneApiTests.cpp`: каждая строка записи окна (`tests/data/window-transcript.jsonl`, её снимает
`tools/record_window_transcript.py`), кроме тех, что окно отвечает одно, проходит через `Scene` и даёт тот же ответ.

## Конверт

Строки JSON: запрос `{"id": .., "op": "имя", "args": {..}}` — ответ `{"id": .., "result": {..}}`, одна строка на
запрос, по порядку. Окно слушает TCP (`--api`), `kinetica-core` — stdin/stdout (`ke::serve`, `src/api/Wire.h`); конверт
у обоих один:

- `id` возвращается как пришёл, любого типа JSON (число, текст, `null`, список, объект); нет `id` в запросе - нет и в
  ответе; `src` игнорируется;
- `args`, который не объект, действует как `{}`; нет `op` или он не текст - операция `""` (ответ «нет операции»);
- список на верхнем уровне - тоже операция `""`; пустая строка пропускается без ответа, `\r` в конце отбрасывается;
- текст не JSON, как и JSON, не являющийся объектом или списком (число, текст, `true`, `null`), получает
  `{"result": {"ok": false, "error": "не JSON: <что> (знак N)"}}` без `id`; слова «что» у хозяев свои (окно говорит
  словами Qt: `not JSON: ...`);
- длина строки не ограничена в `ke::serve` (по трубе говорит свой родитель); ответ сбрасывается в поток после каждой
  строки.

Замок — `tests/WireTests.cpp`: сырые строки записи окна и порядок, сброс и длинная строка.

## Гарантии

- Имя значит одно и то же везде: в окне, в консоли, у агента. Имена не переименовываются — это
  контракт с агентами и MCP.
- Строка аргументов операции — её схема (`src/scene/ArgsSchema.h`): из неё `ops_list` и MCP строят JSON Schema
  (тип, список слов, единица и значение по умолчанию в описании поля). Вызов с полем, которого в строке нет,
  с не тем типом или словом не из списка отвергается с перечнем полей — опечатка не теряется молча. Поля на `_`
  (`_py`) — транспорта, их не проверяют. Поле, которое код читает, обязано быть в строке: иначе вызов окна
  упадёт в самотесте.
- Неудачная команда плагина ничего не меняет: всё, что она успела сделать, откатывается одним шагом.
- `edit_undo` / `edit_redo` отвечают, что изменили: id объектов и мир.
- Правка, пока мир построен (`sim_step`, ▶), классифицируется в `src/scene/LiveEdit.h`: что мир принимает на ходу
  (рабочий цикл привода, свет и камеры, цели ИК, привод сустава) уходит в него и пропадает со Стоп, а то, из чего
  мир построен (тяжесть и физика, группы, массивы, датчики и приводы, тела), останавливает мир и правка
  остаётся. Это сказано в ответе правки, `edit_undo` и `edit_redo` — после правки, а не до неё: `until_stop` —
  мир всё ещё построен, правка действует до Стоп; `play_stopped: true` и `reload` (`world`, `groups`, `arrays`,
  `devices`, `bodies`, `joints`) — правка остановила мир и сохранена, следующий пуск начнётся с кадра 0. Окно
  узнаёт, что форму сустава мир не принял, кадром позже и пока отвечает `until_stop`. Без построенного мира ни
  одного из ключей нет. Замок — `tests/LiveEditTests.cpp` и группа самотеста `live`.
- Каждая правка обратима через ядро правок (`getObject`/`putObject`/`setField`/`removeObject`,
  `getWorld`/`putWorld`) и в окне становится строкой журнала JSON lines, который только дописывается.
- Формат сцены: строка на факт; `save → load → save` даёт тот же текст на любой локали; незнакомая
  строка или роль другой физики отвергается с номером строки и словом.
- Формат сцены — часть API: его строки принимают и отдают `scene_put`, `scene_set`, `scene_get`, `world_set`,
  `world_get`. Он только растёт:
  - ключ назван словом, порядок ключей в строке не важен, пропущенный ключ получает значение по умолчанию —
    файл и скрипт, написанные раньше, читаются всегда;
  - строка и ключ не переименовываются и не меняют смысл и единицу; слова в имени соединяет `_`
    (`contact_hertz`, `anchor_a`), как в аргументах операций;
  - незнакомое слово отвергается, а не теряется молча.

  Имя, которое ключ носил до этого правила (`contactHertz`, `anchorA`…), читается и сохраняется под новым —
  таблица `renamed` в `src/scene/SceneGraph.cpp`; под прежним именем ключ находят и `scene_set`, `scene_get`,
  `world_set`, `world_get` — скрипт и журнал, написанные раньше, работают как работали. Слово-имя (метка, действие
  пульта), которое читается как число, пишется в кавычках (`tags "7"`): кто читает блок по словам (`scene_get`),
  получает слово, а не 7.0. Замок обещания — `tests/data/scene-format-1.kscene`: в нём
  каждая строка и каждый ключ формата на день обещания, файл не правится никогда. Новая строка или ключ —
  в новый файл-образец рядом, не в этот: `scene-format-2.kscene` — слово `kinematic` у роли `rigid` и строка
  `tags` у объекта любого вида; `scene-format-3.kscene` — строка `component` плагина у того, что не фигура;
  `scene-format-4.kscene` — `mass`, `center_of_mass` и `inertia` у роли `rigid`; `scene-format-5.kscene` — `opacity`
  у формы; `scene-format-6.kscene` — `gravity_scale`, `linear_damping` и `angular_damping` у роли `rigid`;
  `scene-format-7.kscene` — `trigger` у роли `collider` и строка `ignores`; `scene-format-8.kscene` — блок `force`;
  `scene-format-9.kscene` — `duration` у строки `world`; `scene-format-10.kscene` — `normal_file` у строки `texture`:
  карта нормалей — картинка нормалей поверхности, зелёный канал вверх (как в OpenGL); пишется, только когда задана,
  и меняет одно освещение, как `bump`.
  Слово `duration` — время проигрывания, секунды от «Пуска», 0 … 86400 (нет слова или 0 — без конца): на этой
  секунде окно ставит сцену на паузу — или, с петлёй у открытой секвенции, пускает её заново — и заканчивает
  запись дубля. Мир из него не строится: правка после «Пуска» берётся на ходу. У `kinetica-core` часов нет, он число хранит.
  Блок `force` (объект «Сила») несёт строку `effect` с ключами `radius shape mode strength` и, только когда заданы,
  `falloff`, `start`, `tag`: слово `falloff`, `start`, `tag` пишется, только когда задано. Строка называется `effect`,
  чтобы не совпасть с блоком по первому слову. У файла нет строки версии: прежняя программа отвергает блок `force` с
  номером строки, как любой вид, добавленный позже. Границы одни у файла, `scene_add_force` и карточки:
  |strength| ≤ 100000, radius ≤ 1000, start ≤ 3600; радиальной нужен radius > 0 — при смене формы радиус задают
  раньше, чем `shape` становится `radial`. Новое слово пишется в файл, только когда оно задано: сцену без него читает и
  редактор, который этого слова ещё не знает.
- Текст сцены разбирает только ядро. `scene_get {id}` отдаёт рядом с текстом блока его вид, имя и строки
  словами (число — числом); `scene_get {id, line, key, count}` и `world_get {line, key, count}` — значения после
  ключа, те самые, что пишут `scene_set` и `world_set {line, key, values}`; чего нет — `null`. Клиент — Python,
  плагин, агент — слова в тексте не ищет.

## Семейства

`scene_*` — список (весь или по виду: `scene_list {kind: "joint" | "body" | "encoder"…}` — из него выбирает поле-ссылка
плагина), блоки файла, добавить, удалить, группы, роли, перемещение; метки: `scene_tag {ids, tag, on?}` ставит слово
на объект любого вида — фигуру, сустав, датчик, батарею, секвенцию, — `scene_list {tag}` находит по нему,
`scene_get {id}` называет метки объекта; `scene_add_force {shape, mode, at?, strength?, radius?}` кладёт силу, как
`scene_add_light` свет, дальше её строка `effect` правится `scene_set`; `world_*` — мир и строка
`physics`; `assembly_*` — магнит сборки, звенья, пресеты, суставы, приводы, датчики, питание, цели IK;
`controller_*` — пульты; `sequence_*` — секвенции (ключи, дорожки, проигрывание). Окно добавляет свои:
`sim_*` (пуск, стоп, шаг, запись дубля), `force_fire {id}` (семейство `force_*`: срабатывание импульсной силы в идущем мире — операция
самого мира, рода «окно», без шага отмены и не правка сцены в журнале), `view_*`, файлы, `plugin_*` (плагины-процессы), `script_run`. Полный список с
аргументами — `ops_list`.

**Скрипт и плагин.** `script_run {file}` запускает файл Python, который строит или меняет сцену и заканчивается —
пример кодом. Скрипт — такой же клиент API, как консоль: `import kinetica as ke`,
`scene = ke.connect()`. Всё, что он сделал, — один шаг отмены; его `print()` приходит в консоль API и в ответ
операции (`output`); упавший скрипт ничего не меняет и называет свой файл и строку; одновременно идёт один скрипт.
`script_stop {}` прерывает идущий: это тот же исход, что падение, — сделанное отменяется, а сцена, оставленная в игре,
возвращается в правку.
Запуск: «Файл → Выполнить скрипт…», ключ `--script файл.py`, любая строка API. Примеры — `examples/scripts/`.
Плагин — другое: он остаётся и даёт редактору новое умение (формат файла, компонент, инструмент, панель, такт) —
[editor-plugin](editor-plugin.md).

## Что проверяют тесты

Сцена без окна (`api/Scene.h`): записанные ответы окна построчно, `ops_list`, построенный мир и правка на ходу, тексты
отказов, файлы, два запуска одного сценария (`scene api:`, `tests/SceneApiTests.cpp`); документ сцены и ход Пуска и
Стопа (`document:`). Программа и Python: `tools/test_scene_core.py` (настоящий `kinetica-core` по трубе) и `tools/test_examples.py` (лестница примеров); оба хозяина рядом —
`tools/test_hosts_agree.py` (свежее окно и `kinetica-core` получают одни запросы, отличия этого раздела утверждены обратным).

Реестр по именам: вопросы, правки, ответы, пакет; поле блока и мира читается и пишется в ядре по
строке и ключу (`actions:`); правки ядра и их обратные, позирование
сустава, сборка, IK, пути целей (`assembly:`); формат сцены (`scene graph:`); образец формата читается и
ни одно его слово не теряется, прежние имена ключей читаются (`scene format:`).
