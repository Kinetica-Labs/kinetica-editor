# Контракты

Редактор собран из ядра и плагинов. Ядро знает только контракты; плагин реализует один контракт и
ничего больше и лежит в `plugins/<контракт>/<имя>/`. Контракт — это заголовок C++ (что вызывать) плюс этот документ (что вызов обязан
значить: единицы, оси, знаки, что гарантируется и что нет) плюс тесты, которые проверяют каждое
обещание на любом плагине. Документ называется по имени контракта.

| Контракт | Заголовок | Плагины | Тесты |
|---|---|---|---|
| [physics](physics.md) — мир твёрдых тел | `src/physics/PhysicsWorld.h` | `plugins/physics/box3d` | `tests/PhysicsTests.cpp`, `tests/SimTests.cpp` |
| [drives](drives.md) — приводы суставов | `src/scene/JointModel.h` (`JointDrive`) | считаются ядром (`src/sim/RobotWorld.cpp`) поверх physics | `tests/SimTests.cpp` |
| [sensors](sensors.md) — датчики робота | `src/devices/*.h`, `SensorObject` в `src/scene/SceneGraph.h` | модели устройств ядра | `tests/DeviceTests.cpp` |
| [editor-plugin](editor-plugin.md) — плагин окна: каждая кнопка есть команда, видна строкой Python | `clients/python/kinetica/plugin.py`, операции `plugin_*` (`editor/PluginHost.h`) | все части окна и сторонние плагины | самотест `KE_EDITOR_TEST=plugin`, `tools/test_plugin_sdk.py`; обхода «каждая кнопка — операция» пока нет (конституция, статья 5) |
| [ui](ui.md) — первый уровень окна: его панели у человека, плагин публикует на второй уровень | `editor/MainWindowPlugins.cpp`, `editor/PluginPanel.h` | все плагины окна | самотест `KE_EDITOR_TEST=plugin` |
| [names](names.md) — имена API: соглашения, грамматика, ступени, словарь, реестр операций; только дополняется | `tests/data/ops-list.json` (ответ `ops_list`) | все операции ядра и окна | `tools/test_names.py` |
| [operations](operations.md) — API редактора; хозяева операций: окно и сцена без окна | `src/scene/SceneOps.h`, `src/api/Scene.h` | реестр операций ядра; окно и сцена без окна — хозяева | `tests/SceneActionTests.cpp`, `tests/AssemblyTests.cpp`, `tests/SceneApiTests.cpp` |

## Плагины: кто угодно может написать свой

**Плагин-процесс — на любом языке.** Отдельная программа (Python, Rust, C++…) подключается к
редактору по тому же API, что и агенты (JSON lines по TCP, `--api <port>`), регистрирует свои
операции — имя, справку, аргументы — и отвечает на их вызовы. Операция плагина сама появляется в
консоли, поиске команд и меню, её видит агент через MCP, она пишется в журнал и отменяется как
родная. Сцену плагин читает и меняет только операциями ядра ([operations](operations.md)). Нет
вопросов совместимости сборок, упавший плагин не роняет редактор. Для импорта и экспорта, генераторов
сцен, анализа, контроллеров и политик робота, связи с ROS и железом. Не годится внутрь шага физики:
задержка сети на тысячи вызовов за кадр.

Контракт — этот документ и заголовок; несовместимое изменение — только с новой версией контракта.
Плагин-процесс объявляет себя вызовом `plugin_register`. Встраиваемых плагинов (`.so` / `.dll`) нет: физика Box3D
собирается внутрь редактора за границей `src/physics/PhysicsWorld.h`.

## Правила для всех контрактов

- Плагин реализует контракт целиком или отказывает явно: метод, которого движок не умеет,
  возвращает ошибку с причиной, а не тихо делает что-то другое.
- Ядро не включает заголовков плагина. Плагин подключает свою стороннюю библиотеку (`extern/`) и
  только в своих файлах — это проверяет задача `ablation` в CI.
- Смена плагина не меняет ни одного теста контракта: если тест пришлось ослабить, плагин контракт
  не выполняет.
- Единицы СИ, правая система, ось Y вверх, углы в радианах (в файле сцены — градусы Эйлера).
- Контракт меняется вместе с документом, заголовком и тестами в одном коммите.
