# Конституция разработки Kinetica

Редактор — кисть, плагины — картины. Мы строим так, чтобы автор — человек или ИИ-агент — за минуты получил
законченную работающую вещь, правил её с откликом меньше секунды без страха (всё отменяется) и не потерял её в
следующем выпуске. Статьи выросли из исследования [docs/design/plugin-sdk-research.md](design/plugin-sdk-research.md)
и из работы над редактором; почему устроено так, как сейчас, — [docs/design/foundations.md](design/foundations.md).
Правила ремесла на каждый день (абляция, абзац в начале файла, контракт одним коммитом, `ke::` вместо `std::`) — в
`CLAUDE.md`; здесь — законы, ради которых они.

## Честность этого документа

Конституция говорит только правду о сегодняшнем дне. У каждой статьи рядом с проверкой стоит, насколько она правда:

- **✅ держится** — проверка есть, работает и ловит нарушение;
- **◐ частично** — что-то проверяется, но меньше, чем сказано; чего не хватает — в «Долгах»;
- **○ намерение** — проверки пока нет: это цель, а не факт.

Пометку «✅» ставят только по проверке, которую можно запустить, и снимают, как только она перестала ловить. Что она
ловит, доказывается от обратного: мутант `tools/mutate.py` ломает закон одной строкой в отдельной копии репозитория, и
заявленный тест обязан упасть (а на неиспорченной копии — пройти). Выживший мутант снимает «✅». Изменение
кода, нарушающее статью, либо исправляется, либо идёт с поправкой конституции (коммит «Конституция: …» с причиной).
Когда закон стал очевиден коду или ушёл в `CLAUDE.md`, статья уходит отсюда: конституция тоже проходит абляцию.

**Чего мы не обещаем.** Плагин-процесс — не песочница: он работает с правами пользователя. Стенд испытателей
(`tools/agent_eval.py`) — средство замера, а не защита. Чужие числа в статьях — гипотезы до наших замеров.

## I. Мир

1. **Одна физика — за контрактом.** Твёрдые тела считает готовый движок за `PhysicsWorld`. Своих решателей, газа,
   жидкостей, ткани, мягких тел нет даже выключенными.
   *Проверка:* ✅ задача `ablation` в CI: словарь нежёсткой физики только в `tests/AblationTests.cpp`, Box3D только в
   `plugins/physics/box3d/`, в `src/` нет Qt.
2. **Робот видит только датчики.** Управление робота — контроллер окна, хук `on_tick` плагина — получает показания
   неидеальных датчиков; истина физики — только роли проверки, и путь к ней задан типом: у контроллера нет ссылки на неё.
   *Проверка:* ◐ `on_tick` получает показания (самотест контроллера по энкодеру); ядро ещё отдаёт `reading()` и
   `truth()` рядом, теста «контроллер не может прочитать истину» нет.
3. **Детерминизм по построению.** Фиксированный шаг, один результат на любом компиляторе, случайность — из генератора
   ядра; настенные часы, `std::*_distribution`, порядок обхода `unordered_*` и fast-math на шаг мира не влияют. Цель —
   шум с ключом (сцена, плагин, объект, стадия): новый плагин не сдвигает чужой шум.
   *Проверка:* ◐ окно и `kinetica-core` дают одни ответы (`test_hosts_agree`), сцена кодом совпадает с окном до бита
   (самотест «window as code»); сравнения хэша сцены GCC и MSVC в CI нет.
4. **Данные, а не код.** Единица у поля — код UCUM и размерность (`core/Units.h`); модель датчика — строка таблицы
   `data/sensors/*.csv`; строка аргументов операции — и справка, и строгая схема (лишнее поле отвергается с его именем,
   значение вне диапазона — с границей). Числа и описания не дублируются в коде.
   *Проверка:* ◐ паспорта и единицы (`tests/CoreTests.cpp`), строгая схема каждой операции (`src/scene/ArgsSchema.h`,
   MCP отдаёт её `inputSchema`); форма окна и `.pyi` из схемы не порождаются.

## II. Действие

5. **API = UI — и для агента.** Всякое действие — операция со схемой; кнопки без операции нет. Встроенное и стороннее
   ходят через один публичный API; MCP отдаёт агенту каждую операцию инструментом — агент может всё, что руки.
   *Проверка:* ◐ реестр операций с видами (`ops_list`), операции «Графиков» и прочих панелей проверены самотестами;
   обхода «каждая кнопка окна — ровно одна операция» нет.
6. **Каждое действие — шаг отмены и строка журнала.** Правка — одна транзакция, Ctrl+Z снимает её; журнал JSON lines
   только дописывается. Команда плагина меняет сцену только операциями ядра; одна команда — один шаг отмены. Сцена без
   окна (`ke::Scene`) журнала не ведёт: сценарий сам себе запись.
   *Проверка:* ◐ `execute → undo` возвращает сцену (`tests/DocumentTests.cpp`), команда плагина — один шаг
   (`editor/SelfTestPlugins.cpp`); `origin` в журнале и отмены по источнику нет.
7. **Имена только растут.** Имя операции, слово аргумента, ключ ответа, слово сцены, имя пакета Python, имя плагина и
   его команды не переименовываются и не исчезают: новое встаёт рядом, старое помечается `obsolete`. Имя плагина —
   его папка латиницей; надписи для человека отдельно от имён.
   *Проверка:* ◐ замок `tools/test_names.py` по `docs/contracts/names.md`; хост берёт имя плагина из папки латиницей
   (`slug`); имена команд плагинов не заперты.

## III. Автор

8. **Без страха и без ожидания.** Плагин — один файл без манифеста и сборки, «Плагины ▸ Новый плагин…» в окне; сохранил
   — перезапустился (цель — ≤ 1 с); ошибка указывает файл и строку; сбой плагина не роняет редактор; законченная вещь —
   за 5 минут.
   *Проверка:* ◐ самотесты: перезапуск по сохранению (около 0,2 с, порогом не утверждается), баннер упавшего плагина с
   файлом и строкой; `test_error_points_at_author`; первые 5 минут не замерялись.
9. **Документация — запускаемые примеры.** Рецепты по 3–10 вызовов; у каждого жеста и кнопки — строка «хочу → как»
   в руководстве (`docs/interface.md`).
   *Проверка:* ◐ лесенка `examples/python` в CI (`test_examples`); таблица «хочу → как» есть только у «Графиков».

## IV. Плагин

10. **Плагин проекта — папка с тестами на стандартной библиотеке.** Ставится копированием папки, без `pip`; тяжёлое —
    `process_pool`, его процессы гаснут с плагином; `test_<имя>.py` идёт без окна и без железа; строка в README
    `kinetica-plugins`.
    *Проверка:* ◐ пул гаснет с плагином (`tools/test_plugin_sdk.py`); тесты есть у `brain` и `depz`, у `formula`,
    `showcase`, `textures` — нет; CI у репозитория плагинов нет.
11. **Надписи на языке окна, перевод — каталог рядом.** Надписи — по-русски, переводы — `i18n/<язык>.json`; описанное
    окно переводит само, составленное на ходу — `tr("…")`; значения вариантов выбора — данные и не переводятся.
    *Проверка:* ✅ самотест `testWords`.

## V. Интерфейс

Интерфейс Kinetica — самый простой и самый удобный, и при этом в нём можно сделать всё, красиво и без перегрузки
панелей.

12. **Мало мест, всё умеет.** Первый уровень окна постоянен и мал — полоса, полка, вид, инспектор, секвенсор, графики,
    консоль, лаборатория — и принадлежит человеку ([ui](contracts/ui.md)). Новое умение, своё или плагина, встаёт на
    второй уровень: меню и Ctrl+K, вкладку инспектора, раздел «Графиков», кнопку полки, рисунок в виде.
    *Проверка:* ✅ самотест `testChart`: запуск, перезапуск и удаление плагина не меняют панели окна, у каждой вкладки
    панели — её ярлык.
13. **Одно состояние, видное, с выходом.** Панель — конечный автомат: картинка из одного значения, события меняют его;
    всё необычное сказано словами там, где на него смотрят, и рядом один выход («Стоп» у мира, «Сбросить вид» у
    графиков).
    *Проверка:* ✅ для мира и «Графиков» (самотесты `play`, `plugin`: слова вида, «Сбросить вид», `plots_get` /
    `plots_set`); остальные панели ещё не сведены к одному значению.
14. **Сначала мировая практика.** Прежде чем рисовать панель или жест — как сделано у лучших (Rerun, Foxglove,
    PlotJuggler, Blender, JetBrains) и почему; жесты знакомые рукам; красота — от меры.
    *Проверка:* ○ держится обзором: образец называется в коммите и в контракте панели (`ui.md`).

## VI. Честность

15. **Честный отчёт, пороги после замеров.** Непроверенное помечено как непроверенное; тест, который не прошёл, назван с
    выводом; пропущенный шаг назван; ошибку признаёт тот, кто её сделал, — человек или агент. Чужие числа — гипотезы,
    пока не померены на нашей машине. Этот документ подчиняется той же статье.
    *Проверка:* ◐ полный самотест, ядро, Python и абляция идут перед коммитом по правилу, а не по замку: 23.11.2026
    коммит 221f208 ушёл до чтения полного прогона с шестью ошибками (исправлено в 0bf4d64).

## Путь

1. **Наблюдаемость кодом:** роль `lab` с истиной, у контроллера — только показания; счётчиковый генератор шума с ключом.
2. **Из схемы — всё:** форма окна, `.pyi` и справка — из одной схемы; `origin` и версия схемы в журнале.
3. **Замки:** обход «каждая кнопка — операция», хэш GCC/MSVC в CI, CI у `kinetica-plugins`, коммит только после
   зелёного самотеста.
4. **Первые пять минут:** испытатели `agent_eval` на простых задачах, медиана и доля успехов с интервалом
   (`agent_eval.py summary`); `kinetica validate`.
5. **Наука проверки:** метаморфные тесты мира (`tests/MetamorphicTests.cpp`) — дальше шаг времени и масса; мутанты на
   каждую «✅»; перебор состояний панелей-автоматов; случайные цепочки операций под санитайзерами.
6. **Встраиваемые C-плагины** — со вторым движком физики: дескриптор `ke_plugin_entry`, интерфейсы по ID, пометки потоков.
