# Секунды до результата решают судьбу плагинов Kinetica

Авторы полюбят SDK плагинов Kinetica не за красоту API. Их удержат три переживания: **законченная работающая вещь в первые минуты**, **петля «сохранил → увидел» короче секунды, где любую пробу можно отменить**, и **уверенность, что написанное не сломается в следующем выпуске**. Психология даёт этому опору. Эффект IKEA срабатывает только при завершённом результате. Живая обратная связь сократила время исправления своих ошибок с 18,5 до 5,6 мин (N=10). Главное препятствие к освоению API — документация и примеры, а не его устройство (50 упоминаний против 36 у Robillard). История экосистем добавляет: плагины умирают от нестабильной границы, в Eclipse 44% сторонних плагинов сидели на непубличном API и ломались. В черновом контракте `docs/contracts/editor-plugin.md` уже есть редкий козырь. Каждое действие окна — именованная отменяемая команда со строкой Python, а встроенное и стороннее устроены одинаково, поэтому работа руками сама превращается в пример кода. Не хватает другого. Схема пока не данные: аргументы операций описаны строкой справки, MCP отдаёт открытую `inputSchema`, а `FieldForm` держит лямбды Qt. Хук компонента получает весь `world`. Нет контракта перезагрузки, состояния, потоков и ролей, а единицы в примере записаны по-русски. Физика и математика дают недостающие правила. Права плагина выражаются типом аргумента: контроллер просто не получает ссылки на истину. Каждая правка — обратимый diff с указанием источника. Шум берётся из счётчикового ГПСЧ хоста, единицы — из схемы и проверяются при загрузке. Оговорка: ни одно найденное исследование DX не изучало именно авторов плагинов. Большинство чисел — самоотчёты, данные о студентах или фольклор DevRel, поэтому целевые значения ниже нужно мерить на своих слепых новичках. Для этого у Kinetica уже есть агенты-испытатели.

*Пометки:*
- ***[н/п]*** — классическая работа, которую исследователи в этой сессии не открывали.
- ***(поиск)*** — факт из поисковой выдержки или вторичного пересказа.
- ***(оценка)*** — расчёт по чужим числам, а не замер Kinetica.

*Часть заметок ссылалась на старый соседний репозиторий PhysRealFlow. Имена переведены на Kinetica: `ke::`, `KE_`, `kinetica`, `.kscene`, `ops_list`, `tools/ke_editor_mcp.py`, `src/devices/Imu.h`. Факты о коде Kinetica сверены с кодом репозитория 19.11.2026.*

## Законченная вещь в первые минуты важнее элегантного API

Самая прочная эмпирическая опора всего дизайна — полевое исследование Robillard и DeLine: всего в нём участвовали более 440 разработчиков Microsoft. В разведочном опросе препятствия, связанные с ресурсами обучения (документация, примеры кода), назвали **50 человек, со структурой API — 36**, с окружением сборки и тестирования — 15 ([Robillard & DeLine 2011](https://www.cs.mcgill.ca/~martin/papers/ese2011.pdf)). Участники ценили не сниппеты на один метод, а **небольшие примеры из нескольких вызовов, которые показывают целый шаблон использования**. Доверяли им только при признаках актуальности: «Those examples would still run but I don't think they have the most recent way of doing stuff». Длинные примеры помогали «getting us going» — скопировать и запустить, — но понимания не давали. Отраслевые опросы повторяют вывод. В опросе Postman 2020 года нехватку документации назвали главным препятствием **54,3% из более чем 13 500 участников** ([Hackernoon о Postman 2020](https://hackernoon.com/54percent-of-developers-cite-lack-of-documentation-as-the-top-obstacle-to-consuming-apis-2v4w3e30)). В 2024 году на первом месте уже несогласованная документация, 39% ([Business Wire о Postman 2024](https://www.businesswire.com/news/home/20241015081863/en)). Отсюда неочевидное следствие для Kinetica: главный рычаг SDK — не очередной метод, а **корпус запускаемых рецептов по 3–10 вызовов**. На каждом рецепте стоит отметка «проверено на версии X», потому что CI прогоняет его на каждом выпуске. И у Kinetica уже есть генератор таких примеров. Консоль печатает строку Python на каждое действие окна, так что автор, пройдя сценарий руками, получает его код. Это автоматическое решение задачи «matching APIs with scenarios» — одного из пяти факторов хорошей документации у Robillard.

Почему первые минуты так важны, объясняет эффект IKEA. В четырёх экспериментах Norton, Mochon и Ariely собственный труд повышал ценность результата **только тогда, когда продукт был завершён**. Разобранная или недоделанная поделка эффекта не давала, а новички ценили свои любительские работы наравне с экспертными ([Norton, Mochon, Ariely 2012](https://papers.ssrn.com/abstract=1777100)). Следствие жёсткое: первый сеанс автора обязан закончиться видимой работающей вещью — кнопкой, которая меняет сцену. Недоделанный учебник хуже, чем никакой. Метрика «время до первого hello world» (TTFHW) повсеместна в DevRel. Twilio называет цель «5 minutes or less», но это заявленная цель, а не замер. Рецензируемой связи TTFHW с удержанием исследователи не нашли ([Nordic APIs](https://nordicapis.com/how-to-measure-the-success-of-developer-relations/)). Есть и встречная позиция: оптимизировать одну TTFHW — значит вводить себя в заблуждение ([Scale Factory 2021](https://scalefactory.com/blog/2021/03/03/optimising-for-mean-time-to-hello-world-considered-harmful), прочитан только заголовок). Поэтому TTFHW нужна не как самоцель, а как проверка того, что первый сеанс доходит до законченной вещи. Мерить её стоит на слепых новичках, медианой и разбросом, и механизм для этого у Kinetica уже есть: `--agent-eval` и агенты-испытатели.

Кто будет писать плагины и зачем, подсказывают опросы участников open source и моддеров. Сильнейший драйвер — удовольствие от творчества (enjoyment-based intrinsic motivation) ([Lakhani & Wolf 2005](https://papers.ssrn.com/abstract=443040)). Через двадцать лет обучение и интеллектуальная стимуляция остаются «highly relevant», а социальные и репутационные мотивы стали встречаться чаще. Новичков ведут карьера, удовольствие, «kinship» и обучение, опытных — альтруизм ([Gerosa et al. 2021, N=242](https://arxiv.org/pdf/2101.10291)). У моддеров деньги и карьера, по пересказу цитирующих работ, на последнем месте, а чувство сообщества и желание помогать сильны ([Poor 2014](https://dblp.dagstuhl.de/rec/journals/nms/Poor14.html)). Sotamaa выделяет пять ориентаций моддеров: playing, hacking, researching, artistic work, cooperation ([Sotamaa 2010](https://dl.digra.org/index.php/dl/article/download/202/202)). Для робототехнического редактора они почти дословно становятся персонами авторов: поиграть с физикой, расширить инструмент, поставить эксперимент, визуализировать, сделать вместе. Теория самодетерминации называет три потребности: автономию, компетентность и связанность ([Ryan & Deci 2000](https://doi.org/10.1037/0003-066X.55.1.68)) [н/п]. Мета-анализ 128 экспериментов предупреждает: **ожидаемые материальные награды, привязанные к выполнению задачи, подрывают внутреннюю мотивацию**, а содержательная похвала её повышает ([Deci, Koestner, Ryan 1999](https://doi.org/10.1037/0033-2909.125.6.627)) [н/п]. На практике это значит:
- автономия — плагину доступно всё, что доступно встроенной кнопке;
- компетентность — мгновенный видимый результат, понятные ошибки и отмена;
- связанность — имя автора на карточке плагина и видимость того, кто им пользуется, но без очков и бейджей за количество.

Форма API тоже измерима. Контролируемые эксперименты показали, что с конструктором по умолчанию (шаблон create-set-call) программисты работают быстрее и ошибаются реже, чем с обязательными параметрами ([Stylos & Clarke, PPIG 2006](https://ppig.org/files/2006-PPIG-18th-stylos.pdf)). Абстрактные фабрики и фабричные методы оказались «significantly more difficult», чем обычный конструктор ([Ellis, Stylos, Myers 2007, в пересказе Stylos et al. 2009](https://memphis-cs.github.io/comp-7085-8085-2012-fall/papers/Stylos2009VLHCC.pdf)). Гибкость API ухудшает удобство ([Piccioni, Furia, Meyer 2013](https://dblp1.uni-trier.de/rec/html/conf/esem/PiccioniFM13)). Теория когнитивной нагрузки и эффект проработанного примера объясняют, почему новичку нужен готовый пример ([Sweller 1988](https://doi.org/10.1207/s15516709cog1202_4)) [н/п]. Эффект обратной экспертизы объясняет, почему тот же учебный шум мешает эксперту ([Kalyuga et al. 2003](https://doi.org/10.1207/S15326985EP3801_4)) [н/п]. Вместе они дают конструктивный довод за **два слоя SDK**. Новичку — шаблон, рецепты и эхо Python. Эксперту — плотный сгенерированный справочник и C-интерфейс без учебной обвязки. Формулы «low floor / high ceiling / wide walls» ([Resnick & Silverman 2005](https://web.media.mit.edu/~mres/papers/IDC-2005.pdf)) [н/п] и «pit of success» ([Atwood 2007](https://blog.codinghorror.com/falling-into-the-pit-of-success/)) — принципы дизайна, а не измеренные эффекты. Для Kinetica они превращаются в четыре конкретных решения:
- низкий пол — однофайловый Python-плагин без манифеста;
- высокий потолок — C-интерфейс к тем же решателям;
- широкие стены — плагины всех видов: команда, компонент, датчик, генератор сцены, импорт;
- «яма успеха» — типы устроены так, что соблюдать контракт наблюдаемости проще всего.

Оговорка: эффект проработанных примеров перенесён из обучения математике и программированию, исследований на освоении SDK не найдено.

## Секундная петля, внятная ошибка и отмена превращают страх в игру

Рамка DevEx сводит опыт разработчика к трём измерениям: скорость и качество обратной связи, когнитивная нагрузка, состояние потока ([InfoQ о DevEx 2023](https://www.infoq.com/articles/devex-metrics-framework)). Опрос в 20+ компаниях связывает значимое время на глубокую работу с самооценкой продуктивности **на 50% выше**. Это самоотчёт, а не замер ([GitHub о DevEx in Action](https://github.blog/research/good-devex-increases-productivity/)). Строже всего — скрытый A/B-эксперимент Google со сборкой. Умеренное ускорение дало небольшой рост удовлетворённости, но главный вывод касается предсказуемости: «if you can't make a process faster or easier, at least make it more predictable so that developers can optimize around it». Зависимость нелинейна: за порогом разработчик переключается на другую задачу, и сокращение с 30 до 20 минут не экономит 10 минут ([Jaspan & Green 2023](https://research.google/pubs/developer-productivity-for-humans-part-4-build-latency-predictability-and-developer-productivity/)). Классические пороги Нильсена такие: 0,1 с — «мгновенно», 1 с — «мысль не прерывается», 10 с — «внимание теряется» ([Nielsen 1993](https://www.nngroup.com/articles/response-times-3-important-limits/)) [н/п]. Они дают целевые точки: **перезагрузка Python-плагина ≤ 1 с, пересборка C++-плагина ≤ 10 с с честным прогнозом времени**. Цикл «правка файла → результат в работающем редакторе» и есть петля обратной связи DevEx для автора плагина Kinetica. Поэтому основная метрика SDK — её латентность и предсказуемость, а не число функций API.

Польза живой среды известна скромнее, чем принято думать. В эксперименте RWTH участники писали на JavaScript, а среда показывала значения переменных после каждой клавиши (N=10). Там **собственная свежая ошибка исправлялась в среднем за 5,6 мин против 18,5 мин** (p = 0,027). Время всей задачи при этом значимо не различалось (p = 0,133) ([Krämer et al. 2014](https://hci.rwth-aachen.de/publications/kraemer2014.pdf)). Контролируемый эксперимент HPI 2025 года (N=37) подтвердил, что живые инструменты интроспекции значимо сокращают отладку. Сами авторы называют прежние результаты области «largely inconclusive» ([Rein et al. 2025](https://arxiv.org/abs/2412.06274)). Работа CHI 1997 дала смешанный эффект, зависящий от вида ошибки ([Wilcox et al. 1997](https://chi1997.acm.org/proceedings/paper/mmb.html)). Значит, горячую перезагрузку стоит продавать как источник уверенности и удовольствия — «поменял строку, сразу увидел, где сломалось», — а не как «вдвое быстрее». Обратный пример сообщество тоже замерило. В Unity правка скрипта замораживает редактор на 12–14 с при компиляции за 2,18 с: время уходит на перезагрузку домена (domain reload) всего процесса, и это стало главной жалобой ([Unity Discussions](https://discussions.unity.com/t/why-is-domain-reload-sooo-slow-and-will-this-ever-be-fixed/798176)). Вывод для Kinetica: перезагружать нужно один плагин, а не процесс, и показывать время каждой перезагрузки.

Ошибки для новичка — основной интерфейс SDK, а не побочный канал. Айтрекинг 56 студентов показал, что на чтение сообщений об ошибках уходит **13–25% времени задачи**. Читать их так же трудно, как исходный код, и трудность чтения предсказывает успех ([Barik et al. 2017](https://jssmith1.github.io/assets/pdf/ICSE_2017_EYE.pdf)). Но данные о пользе «улучшенных» текстов противоречивы. Becker 2016 нашёл снижение числа ошибок ([Becker 2016](https://researchrepository.ucd.ie/entities/publication/d4b1c9ce-e7ff-48e7-b9b9-f0ebe0c15e8e)), а Denny 2014 и Pettit 2017 эффекта не увидели ([Pettit et al. 2017](https://www.aminer.org/pub/599c7b98601a182cd274c8fd/do-enhanced-compiler-error-messages-help-students-results-inconclusive)). Elm и Rust изменили не текст, а *структуру* сообщения. В Rust ошибка «should focus on the code you wrote»: первичная метка на месте ошибки отвечает «что», вторичные — «почему», к ним приложены подсказки ([Rust, «Shape of errors to come»](https://blog.rust-lang.org/2016/08/10/Shape-of-errors-to-come/)). В Elm показ ожидаемого и полученного стал ответом на самый частый вопрос о типовых ошибках ([Elm, «Compiler Errors for Humans»](https://elm-lang.org/news/compiler-errors-for-humans)). Это проектные эссе, а не измерения. Поэтому правило для Kinetica такое. Ошибка указывает на файл и строку автора, а не на кадр C++ внутри редактора. В ней есть «ожидалось / получено» и одно действие для исправления. Эффект проверяется собственным A/B на агентах-испытателях: замеряется время от ошибки до исправления.

Последнее условие — безопасность пробы. В DX Framework среди факторов опыта есть psychological safety и «progress without obstacles». На плохой опыт разработчики реагируют по лестнице: «reducing engagement», затем «no longer speaking up», а крайняя мера — уход ([Greiler, Storey, Noda 2022](https://ar5iv.labs.arxiv.org/html/2205.06352)). В редакторе безопасность пробы держится на двух вещах. Первая — отмена. Если каждый вызов плагина — один шаг отмены, возвращающий граф сцены к прежнему хэшу, экспериментировать не страшно. Архитектура `transact` в Kinetica это уже даёт. Вторая — изоляция сбоев. VS Code держит расширения в отдельном процессе-хосте, чтобы «misbehaving extensions should not impact the user experience» ([VS Code: Extension Host](https://code.visualstudio.com/api/advanced-topics/extension-host)). Bitwig при падении плагина продолжает играть звук, а интерфейс устройства заменяет уведомлением ([Bitwig](https://www.bitwig.com/userguide/latest/vst_plug-in_handling_and_options)). Черновик Kinetica верно делает Python-плагины процессами, поэтому их падение по построению не роняет окно. Про встраиваемые плагины честнее прямо сказать, что им даётся полное доверие.

## Экосистемы гибнут от хозяина: стабильная граница дороже любой функции

Самая сильная количественная находка об уходе авторов — из анализа репозиториев Eclipse. **44% из 512 сторонних плагинов** (1873 версии, 2003–2010) зависели от непубличного non-API и ломались на новых релизах. Плагины только на публичном API имели «very high source compatibility success rate». Большинство из 467 плагинов на SourceForge не развивались дальше первого года ([Businge et al., «Survival of Eclipse third-party plug-ins»](https://research.tue.nl/en/publications/survival-of-eclipse-third-party-plug-ins-2/); [«Eclipse API usage: the good and the bad»](https://ir.must.ac.ug/items/7add37cc-0f43-431c-bbcb-59272f3de709/full)). Если внутренние классы достижимы, около половины авторов ими воспользуются, и их плагины умрут. Firefox показал предельный случай. Старые расширения были «akin to kernel modules», стабильной границы не существовало ([Klotz 2017](https://dblohm7.ca/blog/2017/11/16/legacy-firefox-extensions-and-userspace/)). В Firefox 57 сломались все такие расширения сразу, а помощь авторам свелась к рассылкам, вики и блогу ([Mozilla Add-ons blog 2016](https://blog.mozilla.org/addons/2016/11/23/add-ons-in-2017/)). Bogart и соавторы описывают ломающие изменения как переговоры о том, кто платит. Они отмечают и обратную опасность: экосистема, которая сверх меры ценит стабильность, застаивается и отпугивает новичков ([Bogart et al. 2016](https://core.ac.uk/download/111756963.pdf); [CMU](https://s3d.cmu.edu/news/2016/20160803-breaking-change.html)).

Остальные истории упадка тоже начинаются у хозяина:
- Sketch оставил JS API «soft-deprecated», без журнала ломающих изменений, и ключевые авторы ушли ([Sketch forum](https://forum.sketch.com/t/plugin-development-any-up-to-date-resources-available/4657); [Sketch forum](https://forum.sketch.com/t/whats-happening-to-plugin-support/1678));
- Adobe переводит авторов с CEP на UXP, который, по их словам, делает разработку «much more expensive», и в январе 2026 года они всё ещё спрашивают о сроках ([CC Developer forum](https://forums.creativeclouddeveloper.com/t/concerns-about-migration-of-cep-extension-to-uxp/1049?page=2); [Adobe Community](https://community.adobe.com/questions-606/cep-uxp-roadmap-should-developers-stop-building-cep-plugins-and-what-happens-to-existing-ones-1614807));
- Atom закрыли после нескольких лет без развития ([GitHub blog](https://github.blog/2022-06-08-sunsetting-atom/));
- Unity отменила Runtime Fee в сентябре 2024 года после шока доверия ([Unity blog](https://unity.com/blog/unity-is-canceling-the-runtime-fee));
- Godot сломал бинарную совместимость GDExtension при переходе 4.0→4.1, ещё до того, как API объявили стабильным ([Godot: Upgrading to 4.1](https://docs.godotengine.org/en/4.4/tutorials/migrating/upgrading_to_godot_4.1.html));
- CLAP при стабилизации переименовал ID расширений и ввёл псевдонимы `_COMPAT`, пообещав, что «this kind of break won't happen again» ([CLAP ChangeLog](https://github.com/free-audio/clap/blob/main/ChangeLog.md)).

Противоположный полюс — Factorio. Документация Lua API «is generated directly from the game's source code, so it completely covers all scripting functionalities» ([FFF #294](https://www.factorio.com/blog/post/fff-294)). Штатные разработчики ведут ветки «Upcoming breaking mod changes» и выпустили предварительный changelog к 2.0 ([Factorio forum](https://forums.factorio.com/viewtopic.php?p=619480); [2.0 preview](https://forums.factorio.com/115737)). Они разбирают запросы моддеров к API ([FFF #248](https://cf-www.factorio.com/blog/post/fff-248)) и нанимают сильных авторов: автор мода Space Exploration стал сотрудником Wube ([Earendel](https://www.patreon.com/posts/im-factorio-now-47218319)). Любовь к Factorio держится не на простоте, а на предсказуемости.

По аудитории к Kinetica ближе всего ROS. Жалобы на colcon, CMake и setuptools звучат каждый год, а мейнтейнеры отвечают, что инструменты так задуманы ([ROS Discourse](https://discourse.openrobotics.org/t/ros2-build-tools-systems/35173)). Полевой отчёт 2025 года описывает пять способов сломать сборку виртуальным окружением uv ([uv field report](https://discourse.openrobotics.org/t/uv-on-ros-2-a-field-report-on-workspace-level-virtual-environments-five-failure-modes-and-minimal-colcon-ament-proposals/57111/1)). Анкета пользователей ROS называет сборку новых пакетов барьером перехода на ROS 2 ([Springer](https://link.springer.com/article/10.1007/s41315-024-00393-4)). Урок прост. Python-плагин не должен требовать CMake и рабочего пространства (workspace), а C++-плагин — пересборки редактора. Соседний проект пользователя знает ту же ловушку на стороне Python: тег ABI `cp310` вшит в имя wheel, и смешение версий ломает импорт.

2026 год добавил новую динамику. Obsidian к маю насчитал **более 4000 плагинов и тем и 120 млн загрузок**. С мая он автоматически проверяет каждую версию, а не только первую подачу, и прямо пишет, что ИИ-агенты ускоряют создание плагинов и удлиняют очередь ([Obsidian blog, 12.05.2026](https://obsidian.md/blog/future-of-plugins/)). Тема форума «There are 8,255 plugins as of 2026-09-30. Feeling sad and overwhelmed» (поиск; методики подсчёта расходятся) показывает, что узким местом становятся курирование и поиск, а не входной барьер ([Obsidian forum](https://forum.obsidian.md/t/there-are-8-255-plugins-as-of-2026-09-30-feeling-sad-and-overwhelmed/118891)). Знак доверия без проверки хуже, чем его отсутствие. Исследователи получили синюю галочку «verified publisher» в VS Code для фальшивого издателя, потому что требовалась лишь привязка домена ([Koi Security](https://www.koi.ai/blog/2-6-exposing-malicious-extensions-shocking-statistics-from-the-vs-code-marketplace)). Home Assistant отвечает на это лестницей качества. Уровень Bronze (20 правил) обязателен для входа в core, Silver, Gold и Platinum добавляют правила. Статус каждого правила лежит в репозитории интеграции: done, todo или exempt с причиной. Машина проверяет всё, что можно проверить, остальное — человек ([HA Quality Scale](https://contributors.home-assistant.io/core/quality-scale/)). Плагины Kinetica будут писать и люди, и агенты, поэтому каталог, автоматическая проверка каждой версии и видимые уровни качества нужны с первого дня.

## Частота вызова и срок ответа, а не язык, определяют вид плагина

Деление черновика на плагины-процессы и встраиваемые плагины подтверждается арифметикой. Figma измерила обмен сообщениями через границу песочницы в **~0,1 мс на круг**, поэтому отдаёт плагину копию документа, а не вызов на каждое свойство ([Figma](https://www.figma.com/blog/how-we-built-the-figma-plugin-system/)). Ardour считает так: при буфере в 64 сэмпла (1,3 мс) сессия из 384 плагинов потребовала бы 256–768 переключений контекста за блок, то есть **7,7–23 мс одних переключений**. Поэтому Ardour плагины не изолирует ([Ardour](https://ardour.org/plugins-in-process.html)). Bitwig изолирует их по выбору пользователя, ценой ресурсов ([Bitwig](https://www.bitwig.com/userguide/latest/vst_plug-in_handling_and_options)). На старом стенде ipc-bench TCP даёт около 70 тыс. сообщений/с, общая память — около 4,7 млн ([ipc-bench](https://github.com/goldsborough/ipc-bench)). По этим числам один круг RPC — не меньше двух переключений, около 60 мкс, то есть около 6% такта контроллера 1 кГц ещё до сериализации JSON (оценка). Значит, TCP JSON lines годится для действий пользователя и для обмена раз в кадр одним сообщением «все показания → все команды». Подшаговые вызовы должны жить в процессе редактора.

Протоколы, прожившие десятилетие, подсказывают, как расширить нынешний API Kinetica:
- LSP обменивается возможностями в `initialize`, игнорирует незнакомые поля, считает отсутствующее поле «не поддерживается» и в версиях 3.x обходится без согласования версий ([LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/));
- Jupyter держит отдельный канал Control, чтобы прерывание не ждало в очереди за долгой командой, а по heartbeat находит зависшее ядро ([Jupyter messaging](https://jupyter-client.readthedocs.io/en/latest/messaging.html));
- Chrome MV3 останавливает простаивающий воркер через 30 с, поэтому состояние расширения хранится в хранилище хоста ([Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)).

Для Kinetica последнее значит: состояние плагина хранится в графе сцены и журнале, процесс плагина одноразовый, а перезагрузка — просто перезапуск процесса.

Для встраиваемых плагинов долгоживущие стандарты сошлись на одном рецепте:
- **единственный экспортируемый символ**;
- непрозрачные хэндлы и таблицы C-функций;
- необязательные интерфейсы по строковому ID с версией, NULL означает «не поддерживается»;
- выпущенный интерфейс никогда не меняется, новая версия живёт рядом со старой.

Так устроены CLAP с `get_extension("clap.xxx")` и «C-only ABI, which allows binding to any programming language» ([CLAP](https://github.com/free-audio/clap); [u-he](https://u-he.com/community/clap/)), OpenFX с `fetchSuite(name, version)` и «no symbolic dependency on the host» ([OpenFX](https://openfx.readthedocs.io/en/main/Reference/ofxCoreAPI.html)), VST3 с `queryInterface` и `IComponentHandler2` ([VST3](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/API+Documentation/Index.html)). Шаблон «песочных часов» (hourglass) Du Toit — C++ поверх тонкого слоя C89 поверх C++, без STL, исключений и vtable на границе ([Hourglass, CppCon 2014](https://www.slideshare.net/slideshow/cpp-con-2014-hourglass-interfaces-for-c-apis/38952550)). Зачем он нужен, видно из правил KDE: двоичную совместимость ломают добавление виртуальной функции, перестановка полей и даже новый параметр по умолчанию ([KDE](https://community.kde.org/Policies/Binary_Compatibility_Issues_With_C%2B%2B)). Сегодня `PhysicsWorld` в Kinetica — абстрактный C++-класс с 24 виртуальными методами. Фабрика `makePhysicsWorld` определена в `plugins/physics/box3d/Box3dWorld.cpp` и подключается при сборке (`src/physics/PhysicsWorld.h`). Пока движок один и собирается вместе с редактором, это нормально, но через границу `.so` в таком виде его выпускать нельзя. Два технических урока стоит закрепить заранее. Godot требует, чтобы точность скаляра у расширения и движка совпадала ([GDExtension](https://docs.godotengine.org/en/4.4/tutorials/scripting/gdextension/what_is_gdextension.html)), значит ширина `Real` входит в дескриптор плагина и проверяется при загрузке. Windows проверяет размер структуры (`cbSize`) строго, потому что проверку «не меньше старого» легко обмануть ([Raymond Chen](https://devblogs.microsoft.com/oldnewthing/20031212-00/?p=41523)). Правило именования черновых и финальных интерфейсов (`ke.foo.draft/N` → `ke.foo/1`) надо зафиксировать до версии 1.0, чтобы не повторить разрыв CLAP 1.2.0.

CLAP добавляет то, чего нет в черновике Kinetica, — машиночитаемый контракт потоков. Каждая функция помечена `[main-thread]`, `[audio-thread]` или `[thread-safe]` вместе с условием на состояние плагина. Ресурсы выделяются в `activate()` на главном потоке, а на аудиопотоке запрещены «malloc() and free(), contended locks and mutexes, I/O, waiting». Хост гарантирует, что один экземпляр никогда не работает на двух аудиопотоках одновременно ([CLAP plugin.h](https://github.com/free-audio/clap/blob/main/include/clap/plugin.h); [thread-check.h](https://github.com/free-audio/clap/blob/main/include/clap/ext/thread-check.h)). На Kinetica это ложится один в один. Главный поток — окно и реестр команд, аудиопоток — поток симуляции за `post()`. `activate` соответствует Пуску, `deactivate` — Стопу, `process` — подшагу. Плагин на потоке симуляции не вызывает реестр команд сам, а просит хост выполнить действие на главном потоке. Python на поток симуляции не попадает вовсе: сборщик мусора и GIL несовместимы с правилами реального времени.

Горячая перезагрузка бывает двух видов. Подмена машинного кода (Live++, Unreal Live Coding, jet-live) сохраняет данные процесса, но ломается, когда меняется раскладка данных. Unreal предупреждает, что крупные изменения «will behave unpredictably» ([Unreal Live Coding](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime)). jet-live пишет: «Your app will probably crash if you try to change memory layout», и в многопоточных приложениях перезагрузка ненадёжна ([jet-live](https://github.com/ddovod/jet-live)). Замена модуля с явной передачей состояния переживает смену раскладки, если плагин сериализует своё состояние. Так работает cr.h: `CR_UNLOAD` сохраняет состояние, `CR_LOAD` восстанавливает, а при падении библиотека откатывается к прошлой версии ([cr.h](https://github.com/fungos/cr)). Для Python `importlib.reload` — примитив, а не решение. Внешние ссылки на старые объекты не перепривязываются, экземпляры продолжают жить со старым классом, а C-расширения при повторной загрузке могут сломаться ([Python docs](https://docs.python.org/3/library/importlib.html)). Надёжная схема — хост сам помнит все регистрации плагина. При перезагрузке он снимает их, вычищает пакет плагина из `sys.modules`, импортирует его заново и регистрирует снова. Так устроен Obsidian Hot-Reload: он выключает и включает плагин, когда файлы перестают меняться примерно на 0,75 с ([pjeby/hot-reload](https://github.com/pjeby/hot-reload)). Python-плагины Kinetica — процессы, поэтому их перезагрузка ещё проще: перезапуск. Неисследованный риск: выгрузка C++-библиотек на Linux (`dlclose` при живых `thread_local`, символы `STB_GNU_UNIQUE`) может не дать заменить встраиваемый плагин без Стопа.

Версии везде согласуются по двум осям. Манифест объявляет допустимый диапазон версий хоста. Так делают VS Code (`engines.vscode`, которое «Cannot be `*`») ([VS Code manifest](https://code.visualstudio.com/api/references/extension-manifest)), Blender (`blender_version_min/max` и разрешения с причиной до 64 символов) ([Blender](https://docs.blender.org/manual/en/latest/advanced/extensions/getting_started.html)) и Godot (`compatibility_minimum/maximum`) ([Godot](https://docs.godotengine.org/en/4.2/tutorials/scripting/gdextension/gdextension_file.html)). А о возможностях стороны договариваются уже во время работы. Успешные проекты держат отдельный нестабильный уровень API:
- proposed API в VS Code нельзя публиковать в Marketplace ([VS Code proposed API](https://code.visualstudio.com/api/advanced-topics/using-proposed-api));
- `PyUnstable_*` в Python меняется без предупреждения ([Python C API](https://docs.python.org/3/c-api/stable.html));
- Zed обкатывает новую версию API расширений в ночных сборках ([Zed](https://zed.dev/blog/zed-decoded-extensions)).

У Kinetica есть особенность, которой у других нет: журнал хранит имена и аргументы операций навсегда. Поэтому **схема каждой операции — публичный контракт даже для собственного окна**. Чтобы повторить старый журнал, нужно либо держать старые версии операций, либо регистрировать функцию обновления аргументов для каждой пары (операция, версия).

В безопасности честность важнее иллюзии. Deno прямо приравнивает `--allow-ffi` к `--allow-all`, потому что нативный код в процессе сам делает системные вызовы ([Deno](https://docs.deno.com/runtime/fundamentals/security/)). Принудительно ограничить можно только поверхность API: сервер операций пропускает вызовы по выданным возможностям, как `granted_extension_capabilities` в Zed ([Zed capabilities](https://zed.dev/docs/extensions/capabilities)). Для этого каждое подключение плагина должно быть аутентифицировано, например токеном запуска — как ключ HMAC в файле подключения Jupyter. Сегодня TCP-сервер Kinetica слушает 127.0.0.1 без аутентификации, то есть любой локальный процесс может вызвать любую операцию.

## Схема-данные кормит форму, проверку, справку, агента и тест

Во всех зрелых экосистемах параметры описываются данными, а форму рисует хост. Свой код рисования остаётся лестницей запасных выходов:
- селектор Home Assistant одновременно задаёт допустимые значения и виджет: `number` с min и max становится слайдером, без них — полем ввода, а доменные селекторы `entity`, `area`, `target` снимают большую часть нужды в своём UI ([HA Selectors](https://www.home-assistant.io/docs/blueprint/selectors/));
- Blender различает жёсткий `min`, который молча подставляет минимум («silently assign this minimum»), и мягкий `soft_min`, который ограничивает только перетаскивание ([bpy.props](https://docs.blender.org/api/current/bpy.props.html));
- Obsidian 1.13 перевёл настройки плагинов с императивного `display()` на декларативный `getSettingDefinitions()`, а императивный путь оставил «indefinitely as a fallback» ([Obsidian Settings](https://docs.obsidian.md/Plugins/User+interface/Settings));
- JSON Forms отделяет схему данных от схемы раскладки и разрешает свои рендереры с приоритетом ([JSON Forms](https://jsonforms.io/docs/));
- Houdini привязывает хэндлы во вьюпорте только к параметрам, уже вынесенным на ассет ([Houdini](https://www.sidefx.com/docs/houdini/assets/asset_ui.html)), а две его двери к интерфейсу ассета — Type Properties и Edit Parameter Interface — известная ловушка ([SideFX forum](https://www.sidefx.com/forum/post/292334/)).

Лестница везде одна, ступени по возрастающей цене:
1. данные;
2. подсказки раскладки и условия видимости;
3. свой виджет для типа поля;
4. хэндл во вьюпорте, привязанный к полю;
5. полностью свой UI за каналом сообщений.

Словарь черновика Kinetica (`button`, `slider`, `number`, `toggle`, `choice`, `vector`, `color`, `file`, `text`, `section`, `row`, `label`) — верная первая ступень. Ему не хватает доменных элементов: `entity`, `pose` и `readout` для канала Probe.

Схема окупается, когда из неё генерируется всё остальное. Спецификация MCP 2025-11-25 требует, чтобы `inputSchema` была корректной JSON Schema (по умолчанию 2020-12). Ошибки проверки аргументов возвращаются как результат с `isError: true`, потому что «Tool Execution Errors contain actionable feedback that language models can use to self-correct and retry». При смене списка инструментов сервер шлёт `notifications/tools/list_changed` ([MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)). В официальном Python SDK MCP сигнатура функции сама служит схемой ([python-sdk](https://github.com/modelcontextprotocol/python-sdk)). Stripe проверяет по схеме даже разметку документации, в CI и в редакторе авторов ([Stripe Markdoc](https://stripe.dev/blog/markdoc)). Здесь у Kinetica главный технический долг, в трёх местах:
- `docs/contracts/operations.md` описывает аргументы операции строкой справки (`{target: int, face?: '+x'..'-z'}`);
- `tools/ke_editor_mcp.py` отдаёт агенту открытую `inputSchema` (`additionalProperties: true`), а аргументы вписывает в текст описания;
- `FieldForm` в `editor/InspectorWidgets.h` хранит подпись, диапазон, шаг и единицу как параметры виджета с лямбдами get/set.

Схема из черновика пока существует как намерение, а не как данные.

Шаблоны и валидаторы работают, когда сразу выдают *рабочий* результат и его проверку. `python3 -m script.scaffold integration` в Home Assistant генерирует работающую интеграцию с config flow, тестами и переводами, тут же запускает проверку hassfest и оставляет `TODO`, которые нужно найти до PR ([HA: Create an integration](https://contributors.home-assistant.io/core/integrations/create/)). Godot создаёт плагин из диалога внутри редактора и включает его флажком, «without even reloading the editor» ([Godot](https://docs.godotengine.org/en/stable/tutorials/plugins/editor/making_plugins.html)). В аудио устоялись внешние валидаторы. pluginval проверяет со строгостью от 1 до 10, «5 being generally recognised as the lowest level for host compatibility», фаззит параметры, многократно восстанавливает состояние и отдаёт код выхода для CI ([pluginval](https://github.com/Tracktion/pluginval)). clap-validator по умолчанию запускает каждый тест в отдельном процессе, чтобы падение плагина стало проваленным тестом, а сбой фаззера воспроизводит по seed ([clap-validator](https://github.com/free-audio/clap-validator)). Самый ценный контрактный тест для Kinetica — обратимость. `execute → undo` возвращает граф сцены байт-в-байт, а повтор журнала в чистом процессе даёт то же состояние. Это аналог «multiple state restoration» из pluginval, только для сцены.

Требования к распространению в 2025–2026 годах ужесточились. Microsoft сканирует пакеты и подписывает расширения, а VS Code по умолчанию проверяет подпись (поиск) ([Microsoft](https://developer.microsoft.com/blog/security-and-trust-in-visual-studio-marketplace/)). Open VSX с марта 2026 года требует проверок до публикации (поиск) ([The Hacker News](https://thehackernews.com/2026/02/eclipse-foundation-mandates-pre-publish.html)). Стандартный путь обнаружения Python-плагинов — entry points ([PyPA](https://packaging.python.org/en/latest/guides/creating-and-discovering-plugins/)). Документацию стоит строить по каркасу Diátaxis ([Diátaxis](https://diataxis.fr/)), а для агентов добавить `llms.txt` ([llms.txt](https://llmstxt.org/)).

## Единицы, обратимость и детерминизм должны жить в данных, а не в дисциплине автора

Ошибки единиц в роботах частые и измеримые. Анализ без аннотаций, который выводил единицы из общих сообщений ROS, нашёл несогласованности в **11% из 213 открытых систем** (900 тыс.+ строк). Точность на находках высокой уверенности — 87% (40 из 46), и 33 из 40 верных находок — присваивания величин разных единиц ([Ore, Detweiler, Elbaum 2017](https://par.nsf.gov/servlets/purl/10059721)). В исследовании 2018 года 71 программист расставлял типы единиц в коде и выбирал верную аннотацию примерно в половине случаев (поиск) ([Ore et al. 2018](https://cse.unl.edu/%7Ecarrick/papers/OreEDLASE2018.pdf)). Это довод против того, чтобы заставлять авторов размечать единицы руками. Canelas и соавторы разобрали 180 несоответствий в 115 файлах. Около 29% разобранных случаев (20 из 68) оказались **намеренными**: дифференциальный привод, приближение малых углов. Авторы предупреждают, что если инструмент называет такие случаи ошибками, ему перестают доверять ([Canelas et al. 2024](https://clairelegoues.com/assets/papers/canelas2024physunits.pdf)). Единицы времени компиляции не пересекают границу JSON и Python: F# стирает их при компиляции, и проверять их во время работы «is not possible» ([F# Units of Measure](https://learn.microsoft.com/en-us/dotnet/fsharp/language-reference/units-of-measure)). Стандартная библиотека единиц для C++ (mp-units) нацелена на C++29 ([P3045R7](https://isocpp.org/files/papers/P3045R7.html)), так что ядру на C++17 она не подходит. Вывод: единица — поле схемы. Это строка UCUM ([UCUM](https://ucum.org/ucum)) с вектором размерности, который ядро проверяет при загрузке плагина, а внутри всё хранится в СИ. Правило ROS REP 103 гласит, что драйверы переводят величины до публикации ([REP 103](https://www.ros.org/reps/rep-0103.html)). Но авторское значение и его единица остаются в `.kscene` и журнале, потому что перевод с округлением необратим.

В Kinetica уже видно, зачем это нужно. В `data/sensors/imu.csv` колонка `accel_noise_ug` (теперь `accel_noise_ug_rthz`) у MPU-6050 равна 400. В `src/devices/Imu.h` то же число прокомментировано как «noise density, per sqrt(Hz)». Суффикс теряет /√Гц — это ровно категория «Message Misuse» у Canelas. Кроме того, `ug` в UCUM означает микрограмм, а для микро-g нужен атом стандартного ускорения свободного падения, вероятно `u[g]`. Это не сверено. Целые ли показатели степени в UCUM, тоже не проверено, а от этого зависит, как записать √Гц: дробными показателями в векторе размерности или через форму спектральной плотности (PSD). Решение нужно принять до версии 1.0. Пример в черновике пишет `unit="м"` и `unit="кПа"`. Локализованная подпись подменяет в нём машинный код единицы.

Отмена при нескольких авторах правок проще, чем кажется. Figma отказалась и от OT, и от настоящих CRDT: сервер — единственная точка, которая «can define the order of events». Значение свойства всегда целиком принадлежит одному клиенту, создание и удаление — явные операции, а удаливший клиент хранит данные в своём буфере отмены. Главный принцип отмены: если много раз отменить, что-то скопировать и вернуть правки до настоящего момента, «the document should not change» ([Figma multiplayer](https://www.figma.com/blog/how-figmas-multiplayer-technology-works/)). В Kinetica все изменения тоже идут через один слой операций — окно, TCP, MCP-агент и плагины, — поэтому CRDT и OT здесь были бы чистой стоимостью ([Shapiro et al. 2011](https://www.cs.tufts.edu/~nr/cs257/archive/marc-shapiro/CRDTs_SSS-2011.pdf)). Настоящая проблема нескольких авторов — отмена. Ctrl+Z человека не должен откатывать последнюю правку агента или плагина. Stewen и Kleppmann обосновывают локальную отмену: каждый отменяет свои операции ([Stewen & Kleppmann 2024](https://arxiv.org/abs/2404.11308)). Yjs ограничивает отмену источником транзакции через `trackedOrigins` ([Yjs UndoManager](https://docs.yjs.dev/api/undo-manager)). Для Kinetica из этого следует:
- у каждой транзакции есть `origin`: `user`, `agent:<id>` или `plugin:<id>@<версия>`;
- обратная правка ставит поле обратно, только если его текущее значение равно `after` этой правки, иначе честно сообщает о конфликте с последующим автором;
- команда плагина не мутирует сцену, а составляет команды ядра или возвращает diff, и ядро само выводит обратную правку.

Автор плагина тогда не пишет ни строки кода отмены.

Композиция компонентов лучше всего описана в Drake. Каждая система объявляет состояние, параметры и порты, «Any randomness must come in through a random input port», а диаграмма систем сама является системой ([Drake systems](https://drake.mit.edu/doxygen_cxx/group__systems.html); [Drake stochastic](https://drake.mit.edu/doxygen_cxx/group__stochastic__systems.html)). Сигнальная цепочка паспорта подчиняется простой алгебре. Это математические факты, а не выводы из источника:
- линейные стационарные ступени (усиление, фильтр нижних частот) коммутируют между собой;
- смещение аффинно и коммутирует с фильтром только при единичном коэффициенте фильтра на нуле частот;
- шум до фильтра окрашивается им, а шум после фильтра остаётся белым;
- насыщение и квантование нелинейны и стоят последними.

В `src/devices/Signal.h` Kinetica порядок уже закреплён: чувствительность и смещение, белый шум, фильтр первого порядка, насыщение, отсчёты. Значит, плагин может вставить ступень только в объявленный слот. Переставлять разрешается лишь ступени, объявившие себя линейными стационарными, а размерности по цепочке проверяются при загрузке.

Детерминизм достижим без фиксированной точки. Box2D v3 получил побитовое совпадение между x64 и ARM, MSVC, GCC и Clang. Для этого понадобилось отказаться от fast-math, выключить FMA-контракцию (`-ffp-contract=off`) и написать свои `sinf/cosf/atan2f`. Цена — «no noticeable performance impact», а проверяет всё тест на хэш состояния в CI на каждом PR ([Box2D: Determinism](https://box2d.org/posts/2024/08/determinism/)). ГПСЧ Kinetica (`src/core/Random.h`) уже одинаков на всех компиляторах. Но он хранит состояние: сигнальная цепочка получает `Random*`, и лишнее вытягивание в одной ступени сдвигает все последующие отсчёты. Счётчиковые генераторы Random123 решают это по построению. «A unique (counter, key) tuple will always produce the same result» ([Random123](https://www.thesalmons.org/john/random123/releases/latest/docs/); [Salmon et al. SC11](https://users.cs.utah.edu/~hari/teaching/bigdata/random123sc11.pdf)). Ключом служит `H(seed сцены, плагин, объект, ступень)`, счётчиком — `(тик, канал, номер вытягивания)`. Тогда добавление плагина не сдвигает чужой шум, а любой тик можно пересчитать при повторе журнала. Законы SDK проверяет stateful-тестирование Hypothesis, оно генерирует целые программы, а не только данные. При ошибке Hypothesis печатает «a very short program that will demonstrate the problem» ([Hypothesis](https://hypothesis.readthedocs.io/en/latest/stateful.html)). Законы такие:
- правка, а затем её отмена дают прежний хэш;
- повтор журнала даёт то же состояние, что и живая сессия;
- плагин не сдвигает шум чужих компонентов;
- неверные аргументы отвергаются и не попадают в журнал.

Не проверено: эквиваленты флагов MSVC и период Philox.

## Права плагина на физику задаются сигнатурой, а не документацией

Все зрелые симуляторы делят шаг на три части: «намерение → физика → наблюдение». Запись идёт последовательно и в заданном порядке, чтение — параллельно и только через const:
- в Gazebo PreUpdate и Update пишут в одном потоке в порядке целочисленного приоритета, а PostUpdate получает `const EntityComponentManager&` и выполняется параллельно в нескольких потоках ([gz-sim System.hh](https://github.com/gazebosim/gz-sim/blob/gz-sim9/include/gz/sim/System.hh));
- PhysX формулирует жёстче всех: «It is forbidden to perform write operations in any callback» ([PhysX 5.4.1](https://nvidia-omniverse.github.io/PhysX/physx/5.4.1/docs/Simulation.html));
- в Drake обработчики publish и calculator получают `const Context&`, а «Only the Context is modified by a Simulator; the System is const» ([Drake Simulator](https://drake.mit.edu/doxygen_cxx/classdrake_1_1systems_1_1_simulator.html));
- в MuJoCo пассивный колбэк обязан добавлять к `qfrc_passive`, а не перезаписывать его ([MuJoCo callbacks](https://mujoco.readthedocs.io/en/stable/APIreference/APIglobals.html)).

Подшаг Kinetica (приводы до, датчики после) ложится на эту схему без натяжек:

| Фаза подшага | Кто | Читает | Пишет | Как выполняется |
|---|---|---|---|---|
| `configure` (при Пуске) | любой плагин | свою конфигурацию | только объявления: порты, частота (кратная h), размер состояния, нужный зонд, приоритет | ошибка — отказ загрузки, а не падение |
| `control_tick` (на своей частоте) | контроллер | только показания (`ReadingBus`) | только команды (`CommandBus`) | вне физики, удержание нулевого порядка до следующего тика; может быть процессом или Python |
| `pre_substep` | привод, мировая система | своё состояние, удержанную команду, локальный зонд своего сустава | только добавить силу или момент в своё звено или сустав | последовательно, по приоритету, затем по порядку загрузки |
| `physics` | Box3D за `PhysicsWorld` | — | — | закрыта для плагинов |
| `post_substep` | зонд → устройство | `const`-вид только объявленного объекта | своё состояние и свой слот показания | параллельно, ГПСЧ от хоста |
| `verify` | только роль `lab` | вся физика (const), показания, команды | только журнал | не влияет на траекторию, как `monitor()` в Drake |

Состояние плагина должно быть частью состояния мира. В MuJoCo «Plugin state is considered an integral part of the physics and must be serialized». Непрозрачные данные плагина (plugin data) считаются кэшем и не сериализуются, `reset` обязателен, а экземпляры привязаны к потоку ([MuJoCo extensions](https://mujoco.readthedocs.io/en/stable/programming/extension.html)). Глобальные колбэки `mjcb_*` — известная ловушка: «these are global and not model-specific» ([MuJoCo callbacks](https://mujoco.readthedocs.io/en/stable/APIreference/APIglobals.html)). В батчевом MJX датчики-плагины не поддерживаются вовсе ([MJX](https://mujoco.readthedocs.io/en/stable/mjx.html)). Kinetica здесь уже на правильном пути: модель датчика — строка CSV-паспорта, а не код. Если когда-нибудь появится батч, модели-данные в него войдут, а модели-код — нет. Всё, что влияет на будущие показания, должно быть сериализуемым: фазы часов, состояние фильтров, дрейф смещения, внутреннее состояние привода и контроллера. Иначе отмена, восстановление по журналу и повтор прогона не будут детерминированы.

Контракт наблюдаемости API закрепляет только в одном из изученных симуляторов. В Webots контроллер — отдельный процесс, который видит лишь устройства своего робота, а показания обновляются на `wb_robot_step` ([Webots: Controller Programming](https://cyberbotics.com/doc/guide/controller-programming)). При этом Supervisor объединяет два разных права, «видеть истину» и «менять мир». Даже он не может прочитать внутренние измерения устройств чужого робота ([Webots Supervisor](https://cyberbotics.com/doc/reference/supervisor)). Gazebo отдаёт системе весь ECM, и граница там держится на организации, а не на API: ROS-мосты публикуют только топики датчиков. Genesis показывает ловушку в чистом виде. `read()` и `read_ground_truth()` живут на одном объекте датчика ([Genesis IMU](https://genesis-world.readthedocs.io/en/latest/user_guide/sensing/imu.html)), и утечка истины в управление становится делом одной опечатки. В Kinetica внутри ядра то же самое: `LiveSensor` отдаёт `reading()` и `truth()` рядом (`src/sim/LiveSensors.h`), а Python-клиент `scene.measure()` возвращает «the engine's truth, for checks» (`python/kinetica/__init__.py`). Для ядра и Лаборатории это законно. Но ни один из этих объектов не должен достаться плагину-контроллеру. А черновой хук `frame(self, world)` повторяет именно ошибку MuJoCo (`mjData*` целиком) и Gazebo (весь ECM). Истина при этом ценна. Learning by Cheating учит привилегированного агента на истинной раскладке сцены, а затем — зрительного агента, который её не видит ([Chen et al. 2019](https://arxiv.org/abs/1912.12294)). В asymmetric actor–critic критик учится на полном состоянии, а политика — на изображениях ([Pinto et al. 2017](https://arxiv.org/abs/1710.06542)). Контроллер ANYmal работает на проприоцептивных сигналах ([Lee et al. 2020](https://arxiv.org/abs/2010.11251)), а учитель, по обзорам (поиск), — на привилегированном состоянии. Практика sim-to-real требует обоих каналов, но физически разделённых. Kinetica может закрепить это сигнатурой: у контроллера просто нет ссылки, через которую можно прочитать истину.

Модель паспортного устройства стоит сверить с соседями. Шум датчика в SDF Gazebo задаётся параметрами `mean`, `stddev`, `bias_mean`, `bias_stddev`, `dynamic_bias_stddev`, `dynamic_bias_correlation_time` и `precision` ([sdformat noise](https://github.com/gazebosim/sdformat/blob/sdf14/sdf/1.11/noise.sdf)). Genesis добавляет случайное блуждание, перекрёстную связь осей, разрешение, задержку, кратную `dt`, и джиттер ([Genesis IMU](https://genesis-world.readthedocs.io/en/latest/user_guide/sensing/imu.html)). Chrono — запаздывание (lag) и окно сбора ([ChSensor](https://api.projectchrono.org/classchrono_1_1sensor_1_1_ch_sensor.html)). В цепочке Kinetica по `docs/contracts/sensors.md` есть такт, чувствительность и смещение, белый шум, фильтр, насыщение и отсчёты. Задержки, джиттера, окна сбора и дрейфа смещения пока нет, и это готовые слоты для плагинов-ступеней. Показание полезно отдавать вместе с дисперсией по соглашению ROS `sensor_msgs/Imu`: нули означают «ковариация неизвестна», −1 — «оценки нет» ([Imu.msg](https://github.com/ros2/common_interfaces/blob/rolling/sensor_msgs/msg/Imu.msg)).

Нулевая задержка в цепочке «показание → команда → момент → то же показание» — алгебраическая петля. Drake по умолчанию считает, что каждый вход напрямую влияет на каждый выход (direct feedthrough), и так находит петли до запуска ([Drake LeafSystem](https://drake.mit.edu/doxygen_cxx/classdrake_1_1systems_1_1_leaf_system.html)). Kinetica при загрузке должна требовать хотя бы одну задержку: удержание команды контроллера или задержку устройства. Подшаговые фазы живут в процессе за C-интерфейсом и вызываются пачкой по типу. Контроллер-процесс получает одно сообщение на тик и может считать параллельно с шагом, как `wb_robot_step_begin/_end` в Webots ([Webots Robot](https://cyberbotics.com/doc/reference/robot)).

## Главный вывод

Почти всё, что делает SDK любимым, у Kinetica уже существует в зачатке: операции с обратными, журнал, строка Python на каждое действие, поток симуляции за `post()`, паспорта-данные. Новый слой мало что строит заново, он в основном формализует существующее. Один механизм — операция со схемой, обратной правкой и строкой журнала — одновременно генерирует учебник (эхо Python), даёт интерфейс агенту (MCP), служит эталоном для тестов (закон «правка, затем отмена») и основой перезагрузки (состояние живёт в хосте). Поэтому самый дорогой долг черновика — схема-текст вместо схемы-данных. Пока аргументы — строка справки, ни один из этих четырёх выигрышей не работает.

Второй вывод менее очевиден. Контракт наблюдаемости выглядит как ограничение, но на деле это «яма успеха» SDK. Если у контроллера по сигнатуре нет пути к истине, первый же контроллер новичка честен для переноса в реальность (sim-to-real) по умолчанию. Через API такое даёт только Webots, и то ценой отдельного процесса. В 2026 году автором плагина часто будет ИИ-агент. Строгая схема с `isError`, внешний `validate`, быстрая перезагрузка и отмена по источнику делают успешными и людей, и агентов. Узкое место переезжает в курирование: Obsidian уже упёрся в него.

### Hello world на Python

```python
# ~/kinetica/plugins/hello.py - весь плагин: без манифеста, сборки и регистрации
from kinetica import command, field

@command(label="Уронить куб", key="H", place="Создать")
def drop_cube(scene, height: float = field(1.0, unit="m", range=(0.1, 5.0), label="Высота")):
    """Кладёт куб над началом координат. Пуск - и он падает."""
    scene.add("box", position=(0, height, 0), role="rigid")
```

Id плагина `hello` выводится из имени файла, версия по умолчанию — `0.1.0`. Полный манифест пишет `kinetica package` при публикации. Аргументы команды и есть её схема, как в Python SDK MCP. Панель строится сама: кнопка и ползунок аргумента, как свойства оператора в панели Redo у Blender. Явный `panel()` из черновика нужен только для своей раскладки. Хост выполняет `drop_cube` на главном потоке внутри одной транзакции с `origin = plugin:hello@0.1.0`. Вызов `scene.add` — это команда ядра `scene_add`. Она уже есть (`src/scene/SceneOpsActions.cpp`), и её аргумент `role: rigid` делает тело падающим. Поэтому отмена и журнал работают без кода автора. Попутно видно, зачем генерировать обёртки из `ops_list`: рукописный `Scene.add` в `python/kinetica/scene.py` пока не передаёт `role`, и обёртка отстаёт от схемы операции. Из той же сигнатуры редактор генерирует:
- строку консоли `hello.drop_cube(height=1.0)`;
- запись в `ops_list`;
- инструмент MCP со строгой схемой:

```json
{"name": "hello_drop_cube", "description": "Кладёт куб над началом координат. Пуск - и он падает.",
 "inputSchema": {"type": "object", "additionalProperties": false,
   "properties": {"height": {"type": "number", "minimum": 0.1, "maximum": 5.0, "default": 1.0,
                             "title": "Высота", "description": "м", "x-unit": "m"}}}}
```

Вызов `hello.drop_cube(height=12)` получает ответ `{"ok": false, "error": "height: 12 m > max 5 m"}`, а не молча прижатое значение.

### Hello world на C++

```cpp
// push.cpp - весь встраиваемый плагин: компонент «Толкатель» давит на своё тело постоянной силой
#include <kinetica/sdk.hpp>  // заголовочная обёртка C++ над C-интерфейсом kinetica/plugin.h: ни Qt, ни движка, ни ядра

struct Push {
    ke::sdk::Field<double> force{"force", 2.0, "N", {0.0, 50.0}, "Сила"};  // единица UCUM, жёсткий диапазон

    // [sim-thread] перед каждым подшагом: без malloc, блокировок и ввода-вывода
    void pre_substep(const ke::sdk::Tick&, ke::sdk::Actuate& self) {
        self.add_force({force.get(), 0.0, 0.0});  // только своё тело и только «добавить»
    }
};

KE_PLUGIN("push", "0.1.0", KE_COMPONENT(Push, "Толкатель"));  // экспортирует один символ: ke_plugin_entry
```

```cmake
cmake_minimum_required(VERSION 3.20)
project(push CXX)
find_package(KineticaSDK 1 REQUIRED)
kinetica_add_plugin(push push.cpp)  # .so/.dll в ~/kinetica/plugins; -ffp-contract=off и без fast-math
```

Автор вешает «Толкатель» на куб из инспектора, жмёт Пуск, и куб едет. Пересборка запускается кнопкой Reload или по сохранению файла. Хост меняет модуль на Стопе либо на границе кадра через `save_state`/`load_state`, а при сбое откатывается к прошлой версии. `Actuate` даёт только добавить силу к своему телу, прочитать истину через него нельзя. Компонент без состояния ничего не сериализует. Компонент с состоянием объявляет `ke::sdk::State<...>`, и хост сохраняет его в снимке мира. Хост видит только C-дескриптор, который генерирует макрос:

```c
/* kinetica/plugin.h - всё, что пересекает границу .so */
typedef struct ke_plugin_entry {
    uint32_t struct_size;                           /* хост сверяет строго */
    uint32_t abi_major, abi_minor;                  /* 1, 0 */
    uint32_t real_size;                             /* sizeof(Real): точность скаляра, урок Godot */
    const char *id, *version;                       /* UTF-8, читаются без init: быстрый скан */
    bool (*init)(const ke_host *host);              /* [main-thread] */
    const void *(*get_interface)(const char *iid);  /* "ke.component/1"; NULL - не поддерживает */
    void (*deinit)(void);                           /* [main-thread] */
} ke_plugin_entry;
```

Команду, как в Python-примере, на C++ пишут через ту же обёртку: `d.command("drop_cube", ...)`, внутри — вызов `scene_add`. Понятия те же три: схема, команда, плагин.

### Порядок внедрения

Черновик ставит заготовку, тесты соответствия и навык для агента на пятый шаг. Но именно они составляют первые пять минут, поэтому стоит их перенести:

| Шаг черновика | Что добавить или переставить |
|---|---|
| 2. SDK: `Field/Schema`, `Command`, `UiNode` | `Field` сразу как данные с единицей UCUM и размерностью; генерация JSON Schema и строгой MCP-схемы вместо `OPEN`; `origin` и версия схемы в строке журнала |
| 3. Кнопки из реестра, инспектор из схем, роли — компоненты | `FieldForm` становится рендерером `Field`, а не вторым API; фазы и типизированные хэндлы для компонентов — до появления сторонних компонентов; счётчиковый ГПСЧ и контракт состояния |
| 4. Плагин-процесс, пакет `kinetica` | вместе с ним: супервизор, перезапуск по сохранению, баннер ошибок с файлом и строкой, рукопожатие, токен, мастер «Плагины ▸ Новый…» и `kinetica validate` (перенесено из шага 5) |
| 5. Тесты соответствия, заготовка, навык | расширенный набор законов, уровни строгости, фаззер; рецепты в CI; `llms.txt`, `AGENTS.md`; приёмочный замер «первых пяти минут» на испытателях |
| 6. Встраиваемые с C-интерфейсом — со вторым движком | правила имён интерфейсов, дескриптор (`struct_size`, `real_size`, ABI) и пометки потоков записать в контракт уже сейчас, а реализовать со вторым движком; уровень Wasm для чужих контроллеров рассматривать только после замеров: стоимость копирования через границу Wasm и производительность против нативного кода не найдены ([Wasmtime](https://docs.wasmtime.dev/examples-interrupting-wasm.html); [MSFS](https://docs.flightsimulator.com/html/Programming_Tools/WASM/WebAssembly.htm)) |

Перед тем как закреплять пороги из таблиц, нужны три замера на целевой машине:
- задержка круга по нынешнему TCP JSON lines;
- стоимость шага Box3D;
- стоимость моста через общую память.

Числа в этом отчёте — чужие стенды и оценки по ним, собственных измерений Kinetica пока нет.
