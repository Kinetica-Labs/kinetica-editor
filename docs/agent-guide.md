# Kinetica для агента

Редактор роботов на физике Box3D. Человек видит каждый вызов.
**Каждый вызов — ход около 2 с: меньше вызовов — быстрее.**

## Инженер: истина — измерение, не рассуждение

1. Требование числом и чем его проверить — до первой детали.
2. Начни с готового образца (`assembly_describe`) или простейшего, что движется; по одной части, проверка после каждой.
3. Ось и знак сустава, мотора, датчика — докажи движением: дай «плюс», измерь, куда пошло.
4. Числа — расчётом в СИ с единицами (момент m·g·L, мотор K·V/R); запас момента и тока 1,5–2×.
5. До «Пуска» — `assembly_check`; странность (NaN, улёт, ток у предела) — стоп, пока не объяснена.
6. «Готово» — только с измерением из этого хода.

## Мир

- x вперёд, y вверх (пол на y = 0), z вправо. СИ, углы в радианах; градусы — только в строках `rotation` текста сцены.
- `position` — центр фигуры, `size` — полный размер (у шара — диаметр). Ось цилиндра — его собственная y.

## Берите самый крупный шаг

1. **Готовый робот — один вызов.** `assembly_list`, затем `assembly_add {name, position}`; `overrides` меняет его части
   по имени тем же вызовом: `[{"name": "Батарея 1", "line": "cells", "key": "parallel", "values": [2]}]`.
2. **Земля — один вызов.** `terrain_make {size, height, hills, flat, seed, track}`.
3. **Новый робот — один `scene_batch`.** Шаг `{"as": "имя", "op", "args"}`; дальше `"$имя"` — id, который он выдал,
   `"$имя.key"` — другой ключ его ответа:

   ```json
   {"ops": [
     {"as": "база", "op": "scene_add", "args": {"shape": "cylinder", "position": [0, 0.05, 0], "size": [0.2, 0.1, 0.2], "fixed": true}},
     {"as": "звено", "op": "scene_add", "args": {"shape": "box", "position": [0, 0.25, 0], "size": [0.06, 0.3, 0.06], "role": "rigid"}},
     {"as": "сустав", "op": "assembly_actuator", "args": {"a": "$звено", "b": "$база", "axis": [0, 0, 1], "anchor": [0, 0.1, 0]}},
     {"op": "assembly_drive", "args": {"joint": "$сустав", "target": 0.5}}]}
   ```

4. **Один блок — `scene_put {block}`** (id 0 — новый объект); `scene_get` даёт блоки объектов.

Остальные операции — `editor_call {op, args}`; `ops_list {families: ["assembly"]}` описывает семейство (без
`families` — 100 КБ).

## Темы: прочтите свою до сборки

`guide {topic}`: `engineer` — 15 правил инженера; `api` — карта операций; `film` — съёмка: карточки шагов, формулы, свет, камера; `car` — машинка (колёса, руль, пульт, рельеф); `arm` — рука (суставы с сервоприводами, цель IK, пульт
схвата); `power` — моторы постоянного тока, батарея, драйвер.

## Проверка — четыре вызова

`sim_play` → `sim_step {frames: 120, state: false}` → `sim_measure {objects: [id]}` (каналы `<id>/centre y`, `speed`,
`contacts`… с единицами; `names` — имена по id) → `sim_stop`. Сцена словами — `scene_describe`. Пульт, пока сцена играет: `controller_input {values:
{действие: значение}}`. Посмотреть: `view_screenshot`. Правка во время игры живёт до `sim_stop`.

## Ловушки

- Суставы: `hinge`, `slider`, `ball`, `weld`, `shock` (пружина с демпфером вдоль axis), `cylinder`, `universal`,
  `planar`; `anchor` и `axis` — в мире. `assembly_actuator` — шарнир или ползун сразу с сервоприводом.
- У сустава свои оси: шарнир вращается вокруг своей `rx`, ползун и амортизатор ходят вдоль своей `tx`, куда бы ни
  смотрела axis в мире. Поэтому `dof` шарнира — всегда `rx`.
- Неподвижная опора — `scene_add {fixed: true}`; лёгкое тело — `density: 150` (кг/м³).
- `scene_delete` отвечает `deleted` — всё, что ушло: названное, всё под ним, суставы и датчики на нём.
- Каждый блок текста кончается строкой `end`.
- Своё по образцу: сперва `assembly_describe {name}` — похожая готовая словами; формат целиком не читайте —
  `schema_get {kind}` для незнакомого вида блока.
