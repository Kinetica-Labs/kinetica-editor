# Скрипты на Python — сцена кодом

Скрипт — файл Python, который строит или меняет сцену и заканчивается. Так делают примеры: одну и ту же сцену можно
собрать мышью в редакторе или написать кодом. Только стандартная библиотека Python 3.

**Скрипт или плагин?** Скрипт отработал и ушёл — осталась сцена. Плагин остаётся в редакторе и даёт ему новое
умение: формат файла, компонент с ручками, инструмент, панель, контроллер в такте ([plugins.md](plugins.md)).
Ряд кубиков, пирамида, тележка с датчиком — скрипты. Импорт URDF — плагин.

## Без окна: ke.Scene()

Первая программа — без редактора. `ke.Scene()` запускает `kinetica-core` (`cmake --build build --target kinetica-core`;
в архиве он лежит рядом с `kinetica`; другое место — `executable=` или `KE_CORE`) и отдаёт ту же объектную модель,
что `ke.connect()`. Из корня репозитория: `python3 examples/python/01_hello.py`.

```python
import kinetica as ke

with ke.Scene() as scene:
    box = scene.add("box", position=(0, 1, 0), role="rigid")
    scene.run(1.0)
    print(f"after 1 s the box's centre is {scene.measure(objects=[box])[f'{box.id}/height']:.3f} m high")
```

Печатает `after 1 s the box's centre is 0.120 m high`; от запуска до ответа проходит около 0,03 с.

**Лестница примеров** — `examples/python/`, по одному новому понятию на ступень. Каждый файл запускается из корня
репозитория (`python3 examples/python/02_pendulum.py`), печатает свой результат и проверяется тестом
(`tools/test_examples.py`).

| Файл | Что в нём | Что печатает |
|---|---|---|
| `01_hello.py` | сцена, шаг, замер | куб упал: центр на высоте 0,120 м |
| `02_pendulum.py` | сустав; величина во времени | период маятника 2,011 с — по формуле 2,010 с |
| `03_forces.py` | сила на теле и поле | толчок: 3 м/с ящику в 500 кг; взрыв: 5, 2 и 0 м/с на 0,5, 2 и 4 м |
| `04_motor.py` | команда приводу, энкодер | сказано 30° — энкодер читает 29,70°, сустав на 29,60° |
| `05_sensors.py` | датчик — не истина: шум, смещение | IMU читает 9,43 м/с² вместо 9,81 (в пределах паспорта); сонар 1,449 м из 1,450 |
| `06_cart.py` | робот из частей и цикл управления по датчику | тележка подъехала к стене и встала в 0,45 м по сонару (просили 0,40) |
| `07_arm.py` | готовая сцена, цель ИК, схват | рука UR5e подошла к цели на 3,1 мм, сжала пальцы и подняла кубик на 0,225 м |
| `08_drone.py` | всё вместе: корпус, четыре тяги, IMU, сонар, полётный контроллер | дрон взлетел на 1,02 м, после удара наклонился на 7,3° и выровнялся |
| `09_animation.py` | анимация по ключам: камера, лампа и тело-толкатель | в 1 с камера на полпути (x = 1,00 м); толкатель за 2 с сдвинул ящик с 0,50 до 1,40 м |

Девятая — анимация: ключ — это место и поворот объекта в свой момент, между ключами объект идёт по прямой. В окне ключи
ставит кнопка «◈ Автоключ», в коде — `scene.key(объекты, time=…)`; `scene.seek(время)` ставит бегунок. Тело с ключами в
игре ведётся по дорожке и толкает остальных; камера и свет просто движутся.

Восьмая ступень — целый проект в одном файле: корпус, четыре тяги (силы своего тела, едут и поворачиваются с ним), два
датчика и контроллер шестьдесят раз в секунду. Тягу он задаёт командой, а не правкой сцены:
`scene.command({rotor: {"strength": newtons}})`. В нём три приёма настоящего полётного контроллера, и все — из-за
неидеальных датчиков: ноль гироскопа меряют на земле до взлёта; когда наклонённый сонар теряет эхо, держат последнюю
верную высоту; тягу ограничивают. Чего у дрона нет — датчика места над полом, поэтому после удара его сносит в сторону,
и пример говорит об этом прямо.

Три правила:

- **Пол уже есть** (объект 1, ваш первый получит номер 2); окна, выделения, вида и консоли нет.
- **Путь считается от каталога, где вы запустили скрипт**: `scene.open("a.kscene")`, не найдя файла, называет
  абсолютный путь, который искал.
- **Время идёт только по `run` и `step`**: часов нет, `sim_play` и `sim_pause` отвечают, что их нет. Один вызов берёт не больше 6000 кадров (100 с): остальное отрезается, `completed_frames` в ответе говорит, сколько прошло. После правки, остановившей мир, `scene.time` и скорость тела — `None`, пока `step` или `run` не построят мир заново. Сцену закрывают `with` или `close()`; брошенную закроет сборщик мусора, но не сразу.

Правка, пока мир построен (после `run`), либо уходит в мир на ходу и пропадает со `stop`, либо останавливает мир и
остаётся в сцене: следующий `run` начнётся с кадра 0, а ответ правки говорит `play_stopped: true` и `reload` — что
пришлось перестроить. Так, второе тело после `run` — это перезапуск; что мир принимает на ходу — `src/scene/LiveEdit.h`.

Чего у `kinetica-core` нет, он говорит словами ошибки: `нет операции «view_zoom» в kinetica-core (ops_list называет все её
операции; выбор, вид, консоль, плагины и журнал есть только у окна)`. Операции с `ids` не берут выделение: передайте `ids`.
Журнала нет — скрипт сам себе запись. Все отличия от окна — `docs/contracts/operations.md`, «Хозяева операций».

То же из C++, без трубы (`examples/cpp/hello.cpp`, цель `ke-hello`, запуск из корня):

```cpp
Scene scene("data");                                    // пол с номером 1; таблицы датчиков из ./data/sensors
const Value added = scene.call("scene_add", parseJson(R"({"shape":"box","role":"rigid","position":[0,1,0]})"));
const Value state = scene.call("sim_step", parseJson(R"({"frames":60})"));   // ответ — то же дерево Value, что идёт по проводу
for (const Value& shape : state["shapes"].items())
    if (shape["id"].integer() == added["id"].integer()) std::printf("%.3f m\n", shape["position"].items()[1].number());
```

## Написать

```python
import kinetica as ke

scene = ke.connect()                       # редактор, который запустил скрипт
car = scene.add("box", name="Шасси", size=(0.4, 0.08, 0.26), position=(0, 0.14, 0), role="rigid")
wheels = [car.add_wheel(side) for side in ("front_left", "front_right", "rear_left", "rear_right")]
sonar = car.add_sonar(face="+x")           # дальномер на передней грани
scene.add("box", name="Стена", size=(0.1, 0.5, 1.2), position=(1.65, 0.25, 0), role="collider")
for wheel in wheels:
    wheel.duty = 0.4
scene.run(2.0)                             # две секунды симуляции
print("до стены", sonar.distance, "м")     # показание датчика, как его видит робот
scene.stop()                               # сцена снова как построена
```

`scene` — та же объектная модель, что в консоли редактора: `scene.objects["Куб 1"]`, `scene.add(...)`,
`scene.open(файл)`, `scene.run(секунды)`, `scene.measure(...)`. Для операции, которой в ней нет слова, —
`scene.ed.<операция>(...)`; список операций — `ops_list`. Строку, опробованную в консоли, вставляйте в скрипт как есть.

## Запустить

- в окне: **Файл → Выполнить скрипт…**;
- при запуске редактора: `kinetica --scene examples/ur5e.kscene --script examples/scripts/cubes_row.py`;
- операцией, из консоли, другого скрипта или агентом: `ed.script_run(file="/путь/к/скрипту.py")`;
- из терминала рядом с редактором, запущенным с `--api`: `PYTHONPATH=clients/python python3 скрипт.py`.

## Как он себя ведёт

- Всё, что скрипт сделал в сцене, — **один шаг отмены** (Ctrl+Z).
- `print(...)` виден в **консоли API** под именем файла и возвращается в ответе операции (`output`).
- Упавший скрипт ничего не меняет: построенное до ошибки убирается, а сообщение называет файл и строку —
  `falls.py:5: ZeroDivisionError: division by zero`.
- Одновременно идёт один скрипт. Долгий можно прервать: **Файл → Остановить скрипт** или `ed.script_stop()` — всё, что он
  успел сделать, отменяется, как при падении.
- `scene.run(...)` играет сцену; `scene.stop()` возвращает её как построена — движение в игре не сохраняется.
